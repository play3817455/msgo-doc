## 4. 分析记录

### 4.1 定位过程
1. 名字串引用点 `0xb70f01` 落在处理块 `0xb70ca8`..`0xb71163` 内。
2. 容量经「`mov edx,[eax+78h]`（解码缓冲分配器）+ `push IMM; call edx`」在 `B70CBA` 确证为 `0xA74`。
3. 逐字段按线序读取，类型全部由汇编判定（SOP §6）。
4. 闭合：`B70EB8`（SOP §5.3）。
5. 去向：`vt[0x238]` @`B71147`（7 实参）。

### 4.2 长度闭合与容量口径
- 容量 `0xA74` = 2676 = `312 + (4 + 32×30) + (4 + 128×7) + (4 + 16×31)`：三组数组按「槽步进 × 计数上限」记账（slot 32 / 128 / 16），三处上限由块内 `cmp ebx,1Eh`@`B70D59`、`cmp ebx,7`@`B70DD3`、`cmp ebx,1Fh`@`B70E55` 给出；ms 那 312 是预留槽不接线长。
- 线长 = `303(ms) + 4 + 30·n₁ + 4 + 121·n₂ + 4 + 13·n₃`；四个元素线长由「整函数扫描 + 循环展开」实算：`sub_B43570`=303、`sub_B439D0`=30、`sub_B43C50`=121、`sub_B43D90`=13（交叉校验：48A4 的 `sub_B43A80` = `sub_B43570` 303 + 3×`sub_B439D0` 30 + 8 = 401）。

### 4.3 结构/数组说明
- `ms` 由 `sub_B414C0` 预留单槽 **0x138=312** 后交 `sub_B43570` 消费；`sub_B43570`（`0xB43570..0xB439CE`）**含 8 处定长循环**（`cmp eax,3Dh`×1、`cmp ecx,2`×2、`cmp ecx,3`×2、`cmp ecx,0Ah`×1、`cmp ecx,1`×2、`cmp ecx,7`×4），整函数展开后消费 **303B** ⇒ 结构跨度 312 ≠ 线长 303。成员已逐一具名（`db_design/schema/composites/ms_lounge.json`，打印器 `sub_B49DE0`；与 battle 线形 `ms` 244B / `sub_B06D80` 不同，勿混用）。
- 三组数组的槽步进由预留原语给出：`sub_B05FC0`=0x20/槽、`sub_B414E0`=0x80/槽、`sub_B41520`=0x10/槽；元素线长分别由 `sub_B439D0`/`sub_B43C50`/`sub_B43D90` 整函数展开得到。
- ★**`equip_set` 元素线长 = 121（2026-09-21 修订，此前记 79 系笔误）**：读取器 `sub_B43C50` 逐项累加
  `8(u64 uniq_id) + 2(u16 slot) + 3×4(u32[3] eq_weapon) + 4(eq_shield) + 4(eq_special) + 10×4(u32[10] eq_modules)
  + 4(eq_bonus_modules) + 4(eq_rental_modules) + 43(u8[43] setname)` = **121**，与
  `0x548D`/`0x7172` 两处独立取证（`SC-0x548D` 同一读取器记 121；`0x7172-notes` 明列该累加式）一致，
  也与 `db_design/schema/composites/equip_set.json`（线长 121 / 跨度 123 / 槽 128）一致。
  79 与「槽 128 / 跨度 123」都对不上任何一项累加，属批次-12 的笔误，已同步修正
  `fields.csv`、本 README 与 `_meta/长期记忆.md`。
