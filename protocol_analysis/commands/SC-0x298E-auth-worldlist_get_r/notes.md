# 未决问题 / 反例 / 关联 —— SC-0x298E-auth-worldlist_get_r

## 1. 本命令要点

- 机器草案只抽到 3 个 u32 就止步于 `sub_B02D40`（316/槽数组预留），漏掉整个 `worlds` 数组。
- 容量 `0x278C = 10124 = 12 + 32×316`，与 `0xB03E7D cmp ebx,20h`（32）**精确吻合**（容量是**槽口径**：元素槽步进 316，线上元素只有 309）。
- `auth` 协议类使用**手写游标**（`ebp`/`edi` 指针推进），非 battle/lounge 的 `{cur,end}` 缓冲对象 ⇒ 闭合判据为 `0xB03ED2 cmp ecx,[var_108]`。

## 2. 已定案（原「差 1 未定案」的收口）

| # | 项 | 结论 | 证据 |
|---|---|---|---|
| 1 | 元素线长 | **309** = `4 + 49 + 49 + 193 + 4 + 2 + 4 + 4` | 读取器 `sub_B02E20` 逐字段消费（`worldid` u32 → `name` 49B 循环 → `name_en` 49B 循环 → `desc` 193B 循环 → `stat` u32 → `icon_id` u16 → `client_now` u32 → `client_max` u32） |
| 2 | 槽步进 | **316**（0x13C），与线长无关 | 数组预留 `0xB03E8C`（`sub_B02D40` 预留 0x13C/槽）；容量 `0x278C = 12 + 32×316` |
| 3 | **「193 vs 194」** | **两者都对，量的不是同一件事**：线上 193（读取器循环上界 `cmp esi,0C1h` @ `0xB02E9B`）；内存 194 是「`desc` 首字节 → `stat` 首字节」的偏移差（打印器 `[edi+66h]` → `[edi+128h]`） | `0xC1`=193；`102 + 193 = 295` 不是 4 的倍数 ⇒ `stat`（u32）对齐到内存 296（0x128），中间 **1B 自然对齐填充**。填充在**内存槽**里，不在线上（读取器自己也按内存偏移寻址，`desc` 结束即写 `stat`，游标只前进 193）|
| 4 | 元素内存跨度 | **312**（`client_max` 结束于内存 308+4=312）；槽步进 316 ⇒ 槽尾余量 4B | 打印器按内存偏移寻址：`desc`[+66h] → `stat`[+128h]（1B 填充）→ `icon_id`[+12Ch] → `client_now`[+130h]（2B 填充，u32 对齐）→ `client_max`[+134h]，末成员结束于 312 |
| 5 | 容量口径 | `0x278C` 按槽 316 记（`12 + 32×316`）；按线长算上限 `12 + 32×309 = 9900 = 0x26AC ≤ 0x278C` | `0xB03DDD push 278Ch`；两者不矛盾 |

> 范例记法（本库口径）：**线宽只看读取器消费量**；内存偏移只用于解释槽尺寸。二者不等时一律写成「线宽 N + 槽内 k 字节填充（对齐/尾部）」，不再记成「未定案」。
