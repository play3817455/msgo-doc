## 追加：消费端全链取证 ⇒ 广播建链 + 属主解算（2026-09-30）

**线格式不变**（`from_ent_id(u16)` / `to_ent_id(u16)` / `weapon_itemid(u32)` / `fire_id(u32)`、线长 12、容量 0xC）。

### 1. 分发 → 业务：逐环已钉死

| 环 | 证据 |
|---|---|
| 分发器 case 块 → `vt[0x1DC]`（4 实参） | 本 README §1（块 `0xB1F40F..0xB1F6A1`） |
| `vt[0x1DC]` == `sub_BA9E10` | vftable 直读 `[0xEED7AC+0x1DC] = 0xBA9E10`（`CGVOProtoBattle`） |
| `sub_BA9E10` 转发 → `sub_AFD7C0`，`retn 10h` | `sub_AFD7C0`（4 实参配平） |
| `sub_AFD7C0` → `sub_51A260`（建链） | 直接调用（**无门**，见下 §2 第 1 步） |
| `sub_AFD7C0` → `sub_518940`（解算+上报） | `0xAFD8E5`。`sub_518940` 的**唯一**调用者就是本处 |

### 2. `sub_AFD7C0(from_ent, to_ent, weapon_itemid, fire_id)` 的动作

1. 两个 `ent_id` 各取实体句柄（`sub_4B59B0`）；`to_ent` 不存在 ⇒ 整包不做。
2. 取 `to_ent` 的世界坐标 `v18`，并算一个入参 `sub_515690(v18, 0)`；
3. **无条件**调 `sub_51A260(from_ent, weapon_itemid, 0, v18, …)` ⇒ **建「from → to」的连锁机雷视觉**
   （`sub_51A260` 内部再读 `entity+12` bit0 = 本机拥有位：自机跳过距离门）；
4. **有条件**：`(*(_BYTE*)(*from_ent + 12) & 1) != 0`（**发射方是本机**）才调
   `sub_518940(from_ent, to_ent, fire_id, weapon_itemid)`。

`sub_518940(a1=from, a2=to, a3=fire_id, a4=weapon_itemid)`：
用 `weapon_itemid` 查参数 → 描述符 `*(param+2576)` → 读 byte `+25`（有 `EXP_RANGE`）与 float `+28`（半径）→
清零 284B 暂存区 → `sub_5173F0(to_ent, fire_id, weapon_itemid, 半径, sub_517C60)`（爆点在 **`to_ent`** 上解算，
回调换用带自伤修正的 `sub_517C60`）→ **`sub_B028D0`（完整格式 `CS-0x770D`）**，`weapon_itemid`/`fire_id` 照抄下行。

### 3. 结论

- **这是「服务端委派解算」的第二种形状**：与 `SC-0xEAEA`（属主单播、爆点在实体自身）不同，
  本命令的 **建链视觉对所有客户端都要发生**（每人各画一条连锁），**只有发射方那一台**才解算并回报。
  即：**收件集 = 全房广播**，解算由客户端自己的 `entity+12` bit0 门筛出唯一一台。
- **回报只有完整格式**：本路**没有**短格式分支（对比 `sub_517D50` 的 `sub_474B90` 二选一）
  ⇒ `CS-0xA8FE` 的生产者只有 `sub_4E0D50`（本机开火）与 `sub_AFDCD0`（`SC-0xEAEA`）两条。
- **★`chain_mine` 没有同名上行**：92 条 CS 里**没有任何**命令名带 `chain_mine`
  （`INDEX-命令总表.md` 全表只有本命令 + `SC-0x8D3C weapon_hit_chain_mine` 两行带该词）
  ⇒ 连锁机雷的「开火」在本协议里**只有 SC 侧载体**；若服务端不发本命令，这条武器的建链视觉没有替代来源。
