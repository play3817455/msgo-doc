## 2. 结论摘要

- **报文体总长：定长 `86` 字节（0x56）**，全部由**一个复合结构体** `appear_info` 消费（无顶层基本字段）。
- 结构体由**复合读取器** `sub_B07EC0`（`0xB07EC0`，函数体 `0xB07EC0..0xB0801B`）一次性读入：16 个顶层成员（其中 `snapshot` 为 39B 子结构）合计 **86B**。
- 长度校验：`0xB0D921 mov ebx,[esp+var_1B28]`（游标）、`0xB0D925 cmp ebx,[esp+var_1B24]`（vs 报文末尾）、`0xB0D929 jnz 错误` ⇒ **整包精确消费完**（结构体读取器必须恰好吃掉全部负载）。
- **容量 ≠ 线长**：声明容量 `push 60h`（`0xB0D8C1`）= `96`，等于**内存结构体的 claim**（`0xB0D8ED call sub_B06020` → `0xB0602A add dword ptr [ecx], 60h`），而线长只有 `86`。差值 `10` 字节 = 结构体内对齐全填充（`+2..+3`、`+1Dh`、`+21h..+23h`、`snapshot +25h / +2Ah..+2Bh`、`snapshot 尾部到 +50h` 等）。
  ⚠️ 注意：**成功路径还有最后一次读取**（`0xB08006` 起：`add edi,5Ch; call sub_B02DD0`）——若只在「失败分支 `retn`」处停止扫描，会把结构体误算成 80B。
- 是否分帧：否。
- 关键结论：结构体指针一次交 `vt[0x158]`（`0xB0D9EE` 取虚表项 / `0xB0D9F7` 调用，单实参 = 结构体基址）。
- **机器草案为什么漏扫**：`ida_draft_wire.py` 遇到非 IO 调用即停，本块第一个 IO 调用是**缓冲预留器** `sub_B06020`（`0xB0D8ED`），其后紧跟复合读取器 `sub_B07EC0`（`0xB0D8FC`）⇒ 草案产出「未提取到字段」。本批人工读解两个读取器 + 两个打印器（见 `asm.md`）。

## 4. 分析记录

### 4.1 定位过程
1. 名字符串 `0xEE0410` 的引用点 `0xB0D94F` 落在 `sub_B0CC20` 的 case 块 `0xB0D8AC..0xB0DA13` 内。
2. 错误码 `0x55`（`0xB0D911`、`0xB0D92B`）。
3. 块内**不出现**「预留槽 + 有界读取」对，而是：
   - `0xB0D8ED call sub_B06020`：**缓冲预留器**（`0xB0602A add dword ptr [ecx], 60h` ⇒ claim **96 字节** = 容量）；
   - `0xB0D8FC call sub_B07EC0`：**复合读取器**（结构体逐成员读入并推进线游标）；
   - `0xB0D9AD call sub_B0B4B0`：**结构体打印器**（成员名取证）。
4. 读取器与打印器的成员偏移一一对应 ⇒ 成员名可信（G3）。
5. **两个读取器的「成功路径」各含一次尾读**（`0xB08006`：`add edi,5Ch` + `sub_B02DD0`；`0xB07742`：`add edi,28h` + `sub_B02DF0`）——这是本批的**新坑**（见 `notes.md` 与方法论沉淀）。

### 4.2 长度闭合
- 读取器消费量（§3.1 逐项相加）= **86**；闭合点 `0xB0D925` 要求「游标 == 末尾」⇒ 结构体恰好吃掉全部负载。
- 声明容量 `0x60`=96 ≠ 86 ⇒ **容量不是线长**（规范 §1 铁律 2）：容量 = 结构体 claim。
- 结构体实际跨度校验：打印器最后访问成员 `buildup_eff_range` 在 `+5Ch`（4B）⇒ 跨度 `0x60`=96，与 claim `0x60` **精确相等** ⇒ claim 语义得到双重印证（claim = 结构体尺寸，不是线长）。
- 差值 `96 − 86 = 10` = 内存对齐填充字节总和（`+2..+3`(2) + `+1Dh`(1) + `+21h..+23h`(3) + `snapshot +25h`(1) + `snapshot +2Ah..2Bh`(2) + `snapshot +2Ch..4Fh`(36)… 后者属子结构留白）——**不在线上**。
