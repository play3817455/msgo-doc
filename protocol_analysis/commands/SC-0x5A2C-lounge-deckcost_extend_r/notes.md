## 2.1 `remain` 语义取证（2026-09-24）

原表把 `remain` 记作「剩余次数」，与 `SC-0x8AF0-lounge-deckcost_extend_info_notice`
的 `remain`（表里记「剩余时间」）打架。**逐个查了客户端消费代码，两者写的是同一对槽**：

- 本命令：`vt[0x4C0]` → `sub_BAD780` → `sub_AFA280` → `sub_42DC80(this, result, deckcost, remain)`，
  `result==0` 时落槽 `0x42DD3D`（`this[113766] = deckcost` = `+0x6F198`）与
  `0x42DD37`（`this[113767] = remain` = `+0x6F19C`）。
- `SC-0x8AF0`：`vt[0x4C4]` → `sub_BAD7A0` → `sub_AFA2A0` → `sub_42DD90`，写同样两个槽
  （`0x42DD98` / `0x42DD9E`）。⇒ 同一个字段，两处不能有两种含义。
- 语义判据（决定它是「次数」还是「时长」）：`sub_809070` 的 case 4（打开延长窗口前的前置校验）

```asm
0080917D  mov ecx, [app+6F19Ch]      ; remain
00809183  add ecx, 1Eh               ; + 30
00809186  cmp ecx, 270Fh             ; 9999
0080918C  jle short loc_8091B2       ; 通过 → 开窗
0080918E  push 0FFFFB2CFh            ; 否则 -19761
```

「一次扩容记 **30**」这个粒度与「月」一致，且上限 9999（`0x42E400` 里 `[+6595Ch]==1`
时读该槽的 getter 直接回 `270Fh`=9999，是个「无限」哨兵）⇒ 它是**可叠加的时长**，
不是「可用次数」。故 `SC-0x8AF0` 侧「剩余时间」是对的，本命令原标注系误标。

（`deckcost` 一侧同时钉死：四个写方共用客户端**同一个**上限槽 `app+0x6F198`
（`113766*4`）—— 本命令 `0x42DD3D`、`SC-0x8AF0` `0x42DD98`、`SC-0x68D7` `0x42D9D4`、
`SC-0x063E` `0x4371BC`。其中 `SC-0x063E` 的全量应用器 `sub_437040` 写的正是
`*(__int16 *)(a9 + 24)`，而 `pilot_detail.deckcost` 的 **`memory_offset = 24`（u16）**，
线宽也与本命令的 u16 一致（氏族侧 `SC-0x68D7.deckcost` 是 u32）⇒ 该槽的权威来源是
**机师**列 `game.pilot_detail.deckcost`，本命令回的是**它的新绝对值**，不是本次增量。）
