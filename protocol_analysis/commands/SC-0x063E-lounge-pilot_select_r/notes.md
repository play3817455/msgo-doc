## 与其他命令的关联

- 配对发送侧：`CS-0xF705-lounge-pilot_select`（`sub_B8A8B0`，容量 `0x16`）。
- `pilot_detail` 结构体**被多条命令复用**：本批已见 `SC-0x063E`（本命令）；`SC-0xD286 season_rankerbattle_entry_info` 的块内也出现 `pilot_detail=` 日志。**注意**：各命令的线长必须各自按**该命令调用的读取器**判定（本轮已证明「同一结构体在不同命令里线长可以完全不同」），**不得**因结构体同名就套用彼此的字段表。
- 方法论沉淀（已写入 `_meta/长期记忆.md`）：
  1. **复合读取器必须整函数扫描**：`ida_funcs.get_func()` 取真实边界；「失败出口 `retn`」之后常有成功路径，其中仍可能含读取（本命令 64B → 51672B，`0x057A` 80B → 86B / 37B → 39B）；
  2. **容量 = Σ各字段缓冲 claim**：本命令 `28 + 0xDB10 + 19 + 0x41 + 5 = 0xDB85`；其中 `0xDB10` = 结构体跨度（末成员偏移 + 跨度 = claim，可自校验）、`0x41` = 串槽预算；
  3. **「内存步进 ≠ 元素线长」在数组级也成立**：`favms_arr` 元素线 66B / 内存步进 72B，是 `51672 vs 56080` 差额的主要来源。
