## 4. 分析记录

### 4.1 定位过程
- 分配器指纹：`mov <reg>,[<obj+0Ch>]` → `mov <reg>,[eax+78h]` → `push <容量>; call <reg>` 取得组包缓冲
  （容量申请 `push 0x010E` @ `0xB399DA`）。
- 写线游标：`sub_ABB2F0` 初始化 `{cur,end}`，**游标自 `buf+2` 起**，opcode 占 `buf+0..1`。
- opcode：`0xB39A1A`（`mov     word ptr [esi], 0A8FEh`）。
- 字段名取自**提交（`sub_B02FF0`）之后**的 trace 打印块（`push offset a<Name>; …`），**日志名序 == 线序**。
- 发送去向统一为 `vt[0x58](buf, 负载长度)`（`sub <len>,<buf首址>` = 游标 − 缓冲首址）。

### 4.2 长度闭合
- 上限场景 `2 + 3×4 + 7×(4 + 16×2) + 2 = 268 ≤ 容量 0x10E = 270`（富余 2）

### 4.3 存疑点
- 7 组数组的「计数 + 元素」均为 **u32 计数 + u16 元素**（写线原语 `sub_B02D80` 与内联/`sub_B02DA0`），每组上限 16。
- 数组元素为 u16 ⇒ 元素线长 = 2，与「槽步进」无关（本命令无预留原语，逐元素写线）。
- 容量 `0x10E`=270 与**上限场景线长** 268 相差 2，属精确型容量（上限场景 = 每数组 16 元素）。
- `ent_ids_count` 的写线地址与 `ent_ids` 的元素循环相邻，二者为「计数 + 数组」成对字段（打印块以 `ent_ids={`/`}` 成对出现）。
