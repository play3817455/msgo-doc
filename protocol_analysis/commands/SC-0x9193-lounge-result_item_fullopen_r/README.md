## 4. 分析记录

### 4.1 定位过程
1. 名字串引用点 `0xb6c983` 落在处理块 `0xb6c8b8`..`0xb6ca83` 内。
2. 容量经「`mov edx,[eax+78h]`（解码缓冲分配器）+ `push IMM; call edx`」在 `B6C8CA` 确证为 `0x12C`。
3. 逐字段按线序读取，类型全部由汇编判定（SOP §6）。
4. 闭合：`B6C93A`（SOP §5.3）。
5. 去向：`vt[0x3FC]` @`B6CA67`（1 实参）。

### 4.2 长度闭合与容量口径
- `sub_B41760` @`B6C8FC` 一次推进游标 `0x12C`(=300) ⇒ 该「整块数组」claim = 300，等于 15（循环上界 `cmp edi,0Fh` @`B6C91F`）× 20（槽步进 `add ebx,14h` @`B6C91C`）。
- 元素由 `sub_B45350` 读：`u8 + u32 + u8 + u16` = **8B** ⇒ 线长 = 15 × 8 = 120。

### 4.3 结构/数组说明
- `item_list` = **定长 15 元数组**，无线上 count：循环上界为字面量 `0x0F`（`cmp edi,0Fh` @`B6C91F`）。
- 元素线序（`sub_B45350` @`B45350..B453AD`）：`u8`(→`[edi]`)、`u32`(→`[edi+4]`)、`u8`(→`[edi+8]`)、`u16`(→`[edi+0Ah]`) = 8B。
- 元素打印器 `sub_B4D6E0` 成员名与线序对齐：`id_type=`(u8)、`itemid=`(u32)、`is_itmbox=`(u8)、`amount=`(u16)。
- **元素即 `item_info`**（原记法 `array<struct,15>` ⇒ 按元素宽改挂具名复合体）：
  读取器 `sub_B45350` 函数体消费 8B == `db_design/schema/composites/item_info.json` 的 `length`，
  成员名/内存偏移与该复合体逐项对齐（`id_type`+0 / `itemid`+4 / `is_itmbox`+8 / `amount`+0Ah，与 `SC-0xC4CF` 同一元素形态）。
  槽步进 20（`sub_B41760` claim 300 = 15×20）是该复合体的 `memory_claim`，线长仍按 8×15=120。
  所以 `fields.csv` 写 `array<item_info,15>`，服务端生成 `[]model.ItemInfo`（不再是不透明 `[]byte`）。
