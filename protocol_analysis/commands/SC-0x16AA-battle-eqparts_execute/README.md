## 2. 结论摘要

- **报文体总长：`2 + 4 + 17·N`**（N = `parts_exec` 数量，`0 ≤ N ≤ 416`）。
- 长度校验方式：数组循环结束后 `0xB1077B mov ecx,[var_1B28]`（线游标）／`0xB1077F cmp ecx,[var_1B24]`（vs 报文末尾）／`0xB10785 jz ok`；不等 ⇒ `push 1 / push 0A3h` 报错 ⇒ **闭合点 = 循环之后**（本命令是「计数驱动数组在末尾」的形态）。
- 声明容量：`0x2086`（`0xB10686 push 2086h`）＝ `2(ent_id) + 4(count) + 0x1A0×0x14`（416 个元素 × **缓冲槽步进 20**）＝ **上限场景线长**；元素实际线长 **17** ≠ 槽步进 20 ⇒ 按结构体数组口径记账。
- 计数上限：`0xB10722 cmp ebx,1A0h` / `0xB10728 ja 报错` ⇒ `N ≤ 416`（与容量反推的上限一致，双向印证）。
- 是否分帧：否。
- 关键结论：字段 `ent_id`（u16）与 `parts_exec`（部件效果数组，每元素 6 个子字段），经 `vt[0x20C](ent_id, 数组基址, N)`（`0xB108F6`）交付；元素成员名由元素打印器 `sub_B09130` 确证（`item_id=` / `effect_msec=` / `effect_catego=` / `effect_param=` / `effect_value=` / `effect_value2=`）。

## 4. 分析记录

### 4.1 定位过程
1. 名字串引用点 `0xB107C8` 落在 `sub_B0CC20` 的 case 块 `0xB10671..0xB10912`。
2. 入口 `call sub_B05DA0`（守卫）→ `push 2086h; call [edx+78h]`（容量 8326）→ `sub_ABB2F0` 初始化线游标。
3. 读取：`sub_B413B0`+`sub_B02DF0`（u16 `ent_id`）→ `sub_B02DD0`（u32 计数，上限 `0x1A0`）→ `sub_B06090` 预留（20/槽）→ 循环 N 次调用元素读取器 `sub_B06CF0`（缓冲步进 `0x14`）。
4. 闭合：`0xB1077F`/`0xB10785`（循环之后）⇒ 线体在数组处结束。
5. 去向：`0xB108DE…0xB108F6`，实参序 `(ent_id, 数组基址, N)`。

### 4.2 长度闭合
- 消费量 `2 + 4 + 17·N`（元素读取器 `sub_B06CF0` 整函数消费 `4+4+1+2+4+2 = 17`）。
- 闭合点 `0xB1077F`/`0xB10785` 要求「游标 == 末尾」✓
- **容量反推**：`0x2086 = 8326 = 2 + 4 + 416×20`（`0x1A0 = 416`、槽步进 `0x14 = 20`），与 `0xB10722` 的 `cmp ebx,1A0h` 上限**完全吻合** ⇒ 容量 = 上限场景线长（槽步进口径），元素线长 17 ≠ 20。
- 若按元素线长算上限：`2 + 4 + 17×416 = 7078 ≠ 8326` ⇒ 再次印证「**结构体 claim == 槽步进/跨度 ≠ 线长**」。

### 4.3 存疑点
见 `notes.md`（`effect_catego` 枚举；`vt[0x20C]` 业务定名；`effect_msec` 单位是否确为毫秒）。
