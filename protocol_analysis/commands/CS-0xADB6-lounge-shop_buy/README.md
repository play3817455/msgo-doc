## 4. 分析记录

### 4.1 定位过程
- 分配器指纹：`mov <reg>,[<obj+0Ch>]` → `mov <reg>,[eax+78h]` → `push <容量>; call <reg>` 取得组包缓冲
  （容量申请 `push 0x0382` @ `0xB9CDB6`）。
- 写线游标：`sub_ABB2F0` 初始化 `{cur,end}`，**游标自 `buf+2` 起**，opcode 占 `buf+0..1`。
- opcode：`0xB9CDF2`（`mov     word ptr [ebp+0], 0ADB6h`）。
- 字段名取自**提交（`sub_B02FF0`）之后**的 trace 打印块（`push offset a<Name>; …`），**日志名序 == 线序**。
- 发送去向统一为 `vt[0x58](buf, 负载长度)`（`sub <len>,<buf首址>` = 游标 − 缓冲首址）。

### 4.2 长度闭合
- 上限场景 `2 + 4+1+4+1+1+4 + (25+73+766) = 881 ≤ 容量 0x382 = 898`（富余 17）

### 4.3 存疑点
- 三个变长串的 claim 均为**槽位预算**（25 / 73 / 766），与串实长无关；串后字段偏移浮动 ⇒ 记 `var`。
- 容量 0x382=898 与上限场景线长 881 有 17 字节富余。
- `tab_type` 未在打印块单独打标签（打印器 `sub_ADCBF0` 负责该串，日志串 `tab_type=` 存在）；类型由写线原语 `sub_B061C0` 确证为 u8。
