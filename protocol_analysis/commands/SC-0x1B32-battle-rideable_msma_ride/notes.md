## 追加 2：实参 ↔ 报文字段 ↔ 落点实体 已逐字节钉死（2026-09-30）

### 2.1 实参序 = 线序（1:1，无重排）

vt 调用点 `0xB1167C` 的 8 次 `push` 按「地址递增 = 实参从右到左」读回，与各字段的日志标签
（`result=`@`0xB112F0`、`access_type=`@`0xB11330`、`from_world_id=`@`0xB11354`、`from_pilot_id=`@`0xB11378`、
`from_ent_id=`@`0xB113A0`、`to_ent_id=`@`0xB113C8`、`hp_now=`@`0xB113F0`、`hp_max=`@`0xB11418`）
**逐格同序**；宽度也对上（3 个 `movzx word` 恰落在 `access_type`/`from_ent_id`/`to_ent_id` 三格）：

```
sub_BAA910(a1..a8)          // __stdcall retn 20h，恒等转发
  = sub_AFC9F0(a1..a8)
  = (result, access_type, from_world_id, from_pilot_id, from_ent_id, to_ent_id, hp_now, hp_max)
```

`sub_AFC9F0` 的实参去向（`0xAFC9F0..0xAFCA33` 逐条核过）：

| 实参 | 去处 |
|---|---|
| `result` / `access_type` | 直送 `sub_4BEF10` 的 `arg_0` / `arg_4`（`sub_4BEF10` 里 `cmp [esp+arg_0],0` / `cmp ax,0Bh`） |
| `from_world_id` / `from_pilot_id` | 送 `sub_44FC00`（`ecx = dword_11E3EA8`，`__thiscall`）→ **返回 `from_` 实体的指针** |
| 该指针 | 作为 `sub_4BEF10` 的 `arg_8`（第 3 个）继续下传 |
| `from_ent_id` / `to_ent_id` / `hp_now` / `hp_max` | `arg_C` / `arg_10` / `arg_14` / `arg_18`（原位直送） |

⇒ `sub_4BEF10(this=dword_11E3F94, result, access_type, from_entity_ptr, from_ent_id, to_ent_id, hp_now, hp_max)`，
`this` 是**战斗管理器单例**（`0xAFCA2B mov ecx, esi; esi = dword_11E3F94`），不是实体。

`sub_4BEF10` → `sub_4B9EA0`（`access_type==11`，`retn 14h` = thiscall + 5 栈参）：

| `sub_4B9EA0` 形参 | 实值 | 用途 |

| `this` | `dword_11E3F94`（战斗管理单例） | `sub_4B59B0(this,…)` 的 `this[1]` = 「本地玩家那句的槽号」（`sub_4B59B0` 命中它时返回空哨兵 `dword_11E3EB0`） |
| `a2` | **`from_` 实体指针** | 闸门读 `a2[9]`/`a2[10]`（= 世界/机师 ID） |
| `a3` | **`from_ent_id`** | `v7 = sub_4B59B0(this, &v46, (char)a3)` |
| `a4` | **`to_ent_id`** | `v9 = sub_4B59B0(this, &a3, (char)a4)` |
| `a5` / `a6` | `hp_now` / `hp_max` | `sub_4753F0(a5)` / `sub_475400(a6)`（HUD 血量） |

### 2.2 `+0x440` bit0 的**置位侧 = `from_` 侧**（本命令 = 带身份槽的一侧）

| 分支 | 闸门（`app.world==a2[+36] && (app.pilot==a2[+40] || ≤0) && mode!=10`） | bit0 写 |
|---|---|---|
| `access_type==11` 闸门成立 | = **`from_` 那具就是本地玩家自己** | `*(*v9+1088) &= ~1`（解 **`to_ent`** 侧）→ 随后 **无条件** `*(*v7+1088) \|= 1`（置 **`from_ent`** 侧） |
| `access_type==11` 闸门不成立 | `from_` 是别人的 | 只走无条件的 `*(*v7+1088) \|= 1`（仍置 **`from_ent`** 侧） |
| `access_type==12`（闸门成立才动） | 同 | `*(*v10+1088) &= ~1`（解 **`to_ent`** 侧）+ `*(*v10+1960)=1` + `*(*v10+12)=0x20000` + `*(*v10+0x7A8)=1`；另 `*(*v8+1088) &= ~8`（清 **`from_ent`** 侧的 bit3，非 bit0） |

★所以 A1-1 的答案：**`access_type==11` 的置位对象是 `from_ent_id` 那具**（也就是同时带
`from_world_id`/`from_pilot_id` 身份槽的一侧 = 「乗る側」）；`to_ent_id` 那具只被**解位**
（且仅在 `from_` 是本地玩家自己时）。`access_type==12` 则**完全不置位**，只解 `to_` 侧。
读侧旁证（bit0 实体不跑自身移動更新 / 起身 / 範囲解算）与此互洽：被载着走的是 `from_` 侧。
