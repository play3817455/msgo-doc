# CHARA_MODEL 的「模型ID」调查（`unpackdat/chara/**` ↔ `#5 CHARA_MODEL`）

> 目标：搞清 `#5 CHARA_MODEL`（`msma/msma_model.csv`）里那个"模型ID"到底是什么、怎么填。
> 现状：**机制已彻底破解；逐机映射本地没有，只能重建。**

## 1. ★机制定案（IDA 实测）

### 1.1 模型坐标 = **一个打包十进制数**（不是三个分列）
`sub_473390` 把两个 u32 组成的 **64 位值**用**除 10 的幂**拆成几段：

| 字段 | 分支 A | 分支 B（另一格式） |
|---|---|---|
`+0` (u8) | 格式选择器（决定用哪套路径模板） | `0` |
`+4` (u32) | `v / 1e8`（高位段） | `v / 1e8` |
`+8` (u16) | `(v / 1e9) % 1000` | `(v / 1e6) % 100` |
`+12` (u32) | `(v / 1e4) % 1e5` | `v % 1e4` |
`+16` (u8) | `v % 100` | `v % 100` |

⇒ 以 `101280101` 为例：`+4=1`、`+8=01`、`+12=0101`、`+16=01`（**正是 9 位 モデルID 的形态**）。

### 1.2 路径由代码拼（EXE 里的模板串）
```
chara/%02d/%02d/%04d/attr/MSZ_%02d%02d_%04d_%02d.vra     ← 2/2/4 那套
chara/%02d/%03d/%05d/attr/MSZ_%02d%03d_%05d_%02d.vra     ← 3/5 那套（kind==1 时启用）
（前缀按种类切换：MSZ_ / MAZ_ / BSZ_ / VEZ_ / PLZ_ / BAZ_）
chara/%02d%02d_%04d/MSJ_*.csv
```
调用点：`sub_49D030`（按 `+4` 的 kind 0..7 选前缀）、`sub_5EBB50`（kind==1 → 三位格式）。
参数顺序 = **(系列1, 系列2, leaf, 变体)**；`_01` 即变体位。

### 1.3 于是 モデルID（9 位）的含义
```
モデルID = <种类1> + <系列1(2)> + <系列2(2)> + <leaf(4)>
101280101 = 1 | 01 | 28 | 0101   →  目录 chara/01/28/0101/  ✅ 实测存在
                                     文件 MSM_0128_0101_01.dxg
```

### 1.4 ★CHARA_MODEL 要填在哪两列（**2026-09-15 用反汇编重新定案，旧"69/71"作废 ✗**）
读取器 `sub_571380`：`esi` 就是"当前 CSV 列号"，逐条 `push esi` → `call sub_BBB370/470/4F0` 递增。
★直接反汇编尾部（不再数"第几次读列"，那个口径错了两格）：

| 内存 | 写入指令 | `esi`（=CSV 列号，0 基） |
|---|---|---|
`+436` (0x1B4) | `0x571a01` ← 读于 `0x5719f7` | **第 `71` 列**（低 32 位）★ |
`+440` (0x1B8) | `0x571a11` ← 读于 `0x571a07` | **第 `72` 列**（高 32 位）★ |

⇒ **模型号 = CSV 第 71 列（低 32 位）＋ 第 72 列（高 32 位）**；9 位 モデルID < 2^32 ⇒ **第 71 列写 モデルID、第 72 列写 0** 即可（越界列 = 0，可省略）。
⇒ 消费方 `sub_571BF0` 确实 `sub_473390(*v3, v3[1])` 用这对 64 位值解码路径 ✓（与 `#4 col1` 同一套）。
⚠️ 旧结论（第 69/71 列）是"数读列序号"数错两格 ⇒ **已把写表列从 69 改成 71**（`apply_model_both.py` 同步清掉旧 col69 残留）。

**★拆包已验通**（`sub_473390` 分支B：`+4=v/1e8`、`+8=(v/1e6)%100`、`+12=v%1e4`、`+16=v%100`）：

要还原真实目录 `chara/01/28/0101/`（エールストライク），**只有 `v = 128000101` 满足**：
`+4=1`(→`%02d` 打成 `01`＝第 1 级目录)、`+8=28`(第 2 级)、`+12=0101`(leaf)、`+16=01`(变体＝文件名 `MSM_0128_0101_**01**.dxg` 末两位)。

| 值 | 拆出的路径 | 是否与真实目录一致 |
|---|---|---|
`128000101` | `chara/01/28/0101` | ✅ **一致** |
`101280101`（本地 UI 表的 9 位 モデルID） | `chara/01/01/0101` | ❌ 不一致 |

⇒ **CHARA_MODEL 用的打包值 = `<类别:1><系列:2><leaf:6>`（9 位十进制）**，例 `1|28|000101`；
**★它与本地 `msma_ui_customize/visual_customize` 里的 9 位 モデルID（`101280101`）不是同一套编号，不能照抄★**（那套是客户端 UI 侧的另一套编号，多数在资源树里并不存在）。

## 4.6 ★★「看图识机」通道（2026-09-14 打通；替代"改 C++ viewer"那条路）

**关键发现：界面图标就按 モデルID 命名** ⇒ **每个 chara 目录都能取到它自己的图标**，看图即可判"这目录是哪台机体"：

```

interface/icon/item/s/s0<A><BB><CCCC><NN>.dds   ← 小图
（10 位 = kind0 + A1 + B2 + C4 + NN2，与 sub_473390 的打包值同构；实测 s0101020201.dds 存在 ✓）

```
- 工具：`python datatables/make_unit_icon_sheet.py out.png --series 0101 [--all] [--from N --count M]`
  或 `--map names/模型号映射-补充.csv`（校验收口模式 → 逐条出图 + 打印清单）；
  选项 `--size s|d --cols N --scale N`。**图里标 `#序号`（红）+ 目录 + 代号/机体名**，序号对应 stdout 清单。
- 实测可信：`01/01/1810`→金色百式 ✓、`01/23/0101`→黑色多姆 ✓、`01/84/3001`→艾克西亚 ✓、`01/21/0101`→绿色扎古Ⅰ ✓。
