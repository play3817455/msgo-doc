# 武器数据落地方案（wiki 真值 → `#36` / `#37` / `#78` / `#1`）

> 前情：`#36 item/weapon_battle_detail.csv` 的三列结构已定案（`属性名, 键, 值`，键为**字符串**），
> 但**武器数值**本地/codex 都没有 ⇒ 已从资料站囤到 **6404 行武器真值**（`wiki/wiki_ms_weapons.csv`）。
> 唯一缺的环节是"**武器名 → 武器ID**"。本文件给出该环节的**调查结论**与**落地路线**。

## 1. 桥接调查结论：**按号桥接不可行**（已穷尽）

| 尝试 | 结果 |
|---|---|
| 武器ID 前 6 位 = wiki 机体序号 | ✗ **0 / 54** 命中 |
| 練度ID（7 位，696 个）各种切片/整数变换 = wiki 序号 | ✗ **0 命中** |
| モデルID（9 位，39 个）同上 | ✗ **0 命中** |
| wiki 全文检索「武器ID」 | ✗ **0 命中** |
| wiki 模板命名空间 `武器*` | ✗ **0 页** |
| 客户端本地有无"武器名"表（`str_table.txt` / `fx.csv` / `autoexec.cfg` …） | ✗ 只有特效名与**武器分类名**（`camera_recoil_machinegun/bazooka/…`，反而**交叉印证**了 52 值分类枚举） |
| **事实** | wiki 的 6 位「序号」= **资料站自己的目录编号**（`110986 / 110987 / 110988 …` 连号），**与游戏内部任何 ID 空间都不同源** |

本地唯一存在的对照是 **武器ID ↔ 机体名（日文）**（`weapon_visual_customize` 46 条 + `msma_mesh_customize` 8 条），
例：`214801312/214801612/214801622/214801632 = ギラ・ドーガ(袖付き)の武器`、`213203402 = ガンダムエクシア GNブレイド（二刀流）`
—— **但没有** 武器ID ↔ 武器名。

## 2. ★关键认识：**键的两端都在我们手里**

- 实测（IDA）：`#36` 与 `#34` 的键**都是 `std::string`** —— `sub_5812E0` 用 `sub_596780` 查表、用 `sub_40CE20` 做字符串比较；
  武器对象的**键字符串字段 = `对象 + 2264`**（机体侧同名机制为 `机体行 + 436`）。
- 该字符串**来自服务端下发的 ITEM 行**（武器对象由 ITEM 行构造），而 **`#78 item/item.csv`（表ID 65）本来就是我们要生成的**。
- ⇒ **不必再找"游戏原始武器ID"**：只要 ITEM 行里的字符串与 `#36` 的 `col1` 一致，查表即命中；**键的取值由我们定义**。

## 3. ★稳妥做法：**一把武器写多条键（对冲）**

客户端究竟拿"ID 字符串"还是"武器名"当键，目前**未证实**（需定位 `对象+2264` 的写入点）。因此对同一把武器**同时写多种键形式**：

```
POWER,<武器ID字符串>,4650,
POWER,<武器名>,4650,
MOVE,...（同理）
```

多余的行**永远不会被查到**（无副作用），无论客户端用哪种形式都能命中 ⇒ **一次生成，免猜**。

## 4. 生成计划（四表同源，都来自 wiki）

| 步骤 | 产出 |
|---|---|
| ① 武器清单 | 从 `wiki/wiki_ms_weapons.csv`（6404 行）**按机体页面分组** ⇒ 每台机体的武器列表（名字 + 全参数） |
| ② 机体对齐 | 用**名字**把 wiki 机体 ↔ 我们已有桥表（`names/机体名对照表.csv`：練度ID / 日文名 / codex中文名） |
| ③ `#78 item/item.csv` | 物品ID + **名称（wiki 武器名）** + 类型 `WEAPON` —— **名字写进这一张，UI 才显示得出来** |
| ④ `#37 item/weapon_settings.csv` | col0 = 武器ID；分类/属性/弹道/效果等枚举列（`射击模式`→`sub_596C60`、属性 `SOLID/BEAM/BLAST`→`sub_5964A0`） |
| ⑤ `#36 item/weapon_battle_detail.csv` | `属性名, 键, 值`（键双形式对冲）：**威力→`POWER`｜射程距离→`RANGE`｜集弹性能→`STABILITY`｜连射速度→`RAPIDDELAY`｜装填→`RELOAD`｜锁定→`LOCKON_CAM`｜红锁距离→`HIGH_LOCKON`** |
| ⑥ `#1 msma/msma_weapon_set.csv` | 机体 ↔ 武器槽 ↔ 武器ID（把"每机体武器列表"变成装备关系） |

**取值细则**：wiki 的 `1250 (1375)` 两档值取**第一档**；`POWER` 对 **6 个回复/补给系分类（`REPAIR`=12、`WRESTLE_REPAIR`=43、`RESURRECT`=38、`BULLET_PACK`=24、`REPAIR_PACK`=36、`REPAIR_THROW`=53）写负值**（代码里正是这样取负 ⇒ 负威力=治疗）。

## 5. 需要拍板 3 件事

1. **键范式**：双形式对冲（**推荐，稳**）／只 ID／只名称
2. **武器ID 规则**：`<机体code><2位槽><1位型>`（可读可追溯）／任意流水号
3. **范围**：先做**有 wiki 武器的 367+ 台机体**，还是全 696 台（无 wiki 的按类别兜底）

> 拍板后：新增 `gen_weapon_*.py` 生成器（数据/逻辑分离），产出四张表进 `server/datafiles/`，
> 并登记进 `server/make_datafiles.py` 的 `REAL_FILES`（**漏登记会被占位符覆盖**）。
