# 服务端数据表还原专案（`datatables/`）

> 目标：把 **76 张服务端数据表**（`settings/download_list.csv` 清单）的**内容**逐张还原出来，
> 让客户端进大厅后能拿到"讲得通"的数据，而不是空占位。
>
> 前置成果（已完成，见 `../reverse-login-chain/formats/`）：
> - **格式**：79 张表的**列定义**已全部解出（78/79 有列、**1155 个列位、0 处未解析**）
> - **枚举**：30 个枚举类型共 **599 条名↔值**
> ⇒ 本专案只剩"**往列里填什么**"这一件事。

---

## ★ 专案规则（用户 2026-09-14 口述，生效，逐条遵守）

1. **内容是"资源 + 参数"**：这些文件无非是**和资源对应 + 一些参数**，不存在需要凭空发明的语义。
2. **三条腿配合作推断**（不必联调、不必等真服务端）：
   - **(a) `data/` 资源文件** = `unpackdat/` 下的资源族 —— `chara/`(118230)、`item/`(11791)、`interface/`(43358)、`fx/`(10776)；
   - **(b) 汇编逻辑** = 客户端读取函数（`sub_BBB370`/`456D90`/`BBB4F0`…）与业务回调的用法 ⇒ 推断**每列是什么意思**；
   - **(c) 外部资料** = `unpackdat/codex/data/units.json`（官服停运后从 B 站高达WIKI「机体对比工具」导出的
     **699 台机体数值**：armor/shield/speed/boost/payload/down/cost/terrain…）。
3. **本专案独立成文件夹**：所有产物只进 `datatables/`，不改动 `reverse-login-chain/` 与 `server/` 的既有结论。
4. **每张表必须写注释**：
   - **用途（启发）** —— 这张表是干什么的；
   - **每一列大概用来做什么** —— 逐列注释；
   - 不确定的一律标 `⚠️`（或"待定"），**不许把推断伪装成结论**。
5. **先记录、后还原**：逐个文件推进，进度写进 `03-还原进度.md`（列已注释 → 有内容 → 数值已校准）。

## 怎么用（下一步的推进方式）

1. 打开 `00-表清单与用途.md` → 按 **★ 主表**（`CHARA_PARAM` / `CHARA_MODEL` / `ITEM`）优先；
2. 进 `01-列注释/<表>.md` 看逐列注释与"填写规则"；
3. 填内容时三处取证：`unpackdat/<资源族>` 里有没有对应条目 → 汇编里这一列被谁用、怎么用 → 外部资料（codex）有没有现成数值；
4. 填完更新 `03-还原进度.md`，并把"依据"写清（哪条资源 / 哪个函数 / 哪份外部资料）。

> ⚠️ 铁律提醒（`topics/16 §三`）：CSV 必须 **UTF-8 无 BOM** + **CRLF** + 数据行**带尾逗号** +
> `#` 行跳过；**越界列读作 0**，所以只需写到你真正要设的最大列号。
