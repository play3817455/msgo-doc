## 0. ★头号发现：客户端下载到的**不是** `server/datafiles/` 里的种子 CSV，而是**库的导出**

这一条推翻了本仓多份文档（含 `36-36-WEAPON_BATTLE_DETAIL.md` §4 我昨天写的那句
"CSV 是客户端要下载的那份下发件"），必须先立住：

| 环节 | 证据 |
|---|---|
| 运行时**只读库**，不读盘 | `serverv/internal/cfg/dbstore.go`：`// Runtime must not read CSV from disk.`；`Refresh()` 从 `meta.cfg_manifest` 取 `filepath -> raw_csv` |
| 下发的 CSV 字节是**从库行拼出来**的 | `serverv/internal/cfg/csv_export.go::ExportTableRawCSV` —— 取 `information_schema.columns` 里**除 `_row_id` 外的全部列、按物理序**，`ORDER BY _row_id`，每行补尾逗号 |
| 谁把它写进 manifest | `serverv/internal/cfg/sync_db.go::exportManifest()`（`raw_csv` / `row_count` / `sha256`） |
| 客户端的种子 CSV 只是一次性回灌 | `cfgsync` 的 `-bootstrap-csv` 帮助串：`"optional one-time CSV tree for empty tables (runtime CSV is DB-only)"`；`grep bootstrap` 只在 `-recreate` 路径用它 |
| 改库后必须**重导出**才能让客户端看到 | 仓内已有先例并写明了命令：`01-列注释/66-58-PLAY_BONUS_REWARD.md` §"客户端下载到的那份 CSV = `meta.cfg_manifest.raw_csv` … `go run ./tools/cfgsync … -export-only -migrate=false`" |

⇒ **口径链条**：`脚本改库` →（必须）`cfgsync -export-only 重导 manifest` → `0xF86A 下发给客户端`。
**种子 CSV（`server/datafiles/lounge/**`）与客户端看到的内容没有直接因果关系**，它只在空表回灌时用过一次。

## 1. `#37` 逐列建账（判据：`serverv/static/cfg_schema.json` 的 `csv_index`）

`cfg_schema.json` 给出 IDA 实测的「CSV 位置 → 库列名」映射（148 列全部有 `csv_index`，
且其顺序与库的物理列序**逐位相同**）。按此把两边对齐后逐键逐列比：

- CSV（种子）**1652** 键 / 库 **1645** 键 / 共有 **1645**
- **只在 CSV 7 键**（库里整行没有）：`212301109` / `212301110` / `223005102`（sidecar 族）
  + `12010101` / `12840101` / `13200151` / `13200251`（8 位族）
- **只在库 0 键** ⇒ 库 ⊊ CSV（库是**旧快照**，不是"另一套更全的数据"）
- **20 列有差异，128 列完全一致**

### 1.1 三组结论

**A 组：12 列 = 库侧占位（自证），种子 CSV 无此列　⇒ ★语义已被 §8 改判★**

`ammo_type_id` + 11 个 str 列（`effect_name_list` / `hit_effect_list` /
`muzzle_effect_list` / `trail_effect_list` / `sound_set_list` / `voice_set_list` /
`camera_shake_list` / `screen_flash_list` / `buff_effect_list` / `debuff_effect_list` /
`spawn_effect_list`），各 **1645/1645 行**，且

- 那 11 个 `*_list` 列：库值 **100% 等于键本身**（`1010401` 那行就写 `1010401`）—— 占位自证，无需再猜；
- `ammo_type_id`：库值 **100% 是常量 `'1'`**。

出处已定位 = `datatables/load_paired_ms_db.py`（唯一写这 11 列的地方）：

```python
# load_paired_ms_db.py:394-415（update 分支）/ 421-429（insert 分支）
                          ammo_type_id = '1',
                          effect_name_list = %s,   # ← 传进去的是 iid
                          hit_effect_list  = %s,   # ← iid
                          ...（共 11 列全是 iid）
```

⚠️ **本节原先把这 11 列当"特效/音效名列表"、并据此推断"占位值解析不到任何资源 ⇒ 等价于空"——
该推断已作废。** 用 13338 `ida-mcp`（`GundamOnline_CHINA_v15.exe.i64`）直证：
这 11 列是 **`#37 → #36 WEAPON_BATTLE_DETAIL` 的 11 张子表连接键**
（POWER/RANGE/HIGH_LOCKON/STABILITY/RAPIDDELAY/COOLTIME/RELOAD/LOCKON_CAM/RECOIL/SWITCHTIME/SHIELD），
客户端拿它们查 `#36`（不是查 `fx.csv`），**查不到一律按 0 兜底**。
⇒ 库里的自连接值 **能命中 #36、是有用的**；**"空"才是必然 miss（属性全 0）**。
完整证据链与动作见 **§8**。

**B 组：4 列 = 8 位 icon-id 族，库权威、种子 CSV 旧**

| 列 | 差数 | 族 | 种子 CSV | 库 |
|---|---|---|---|---|
| `model_id_hi` | 14 | 全是 8 位族 | `0` | 空 |
| `magazine_size` | 11 | 全是 8 位族 | 空 | `1/14/27/45…` |
| `damage_attribute` | 14 | 8 位族 | `GUN_RAPID`/`SOLID` | 空 |
| `weapon_attribute` | 14 | 8 位族 | `SOLID`/`BEAM` | 空 |

种子 CSV 里这 24 行的出处是**更早的占位管线** `gen_weapon_pipeline.py`（它只写 34 个字段，
`NUMCOL` 下标与 #36 同一套错位口径）；库侧是 `load_paired_ms_db.py`（`units.json` 归并）。
与 `#36` §6.4 定案同构 ⇒ **8 位族一律库权威，方向 库 → CSV**（`#36` 已经这么做了）。

**C 组：6 列 = sidecar 族内容分歧，种子 CSV（当前生成器）权威**

| 列 | 差数 | 典型（键：CSV vs 库） | 判谁对 |
|---|---|---|---|
| `damage_attribute` | **372** | `csv='GUN_RAPID'` / `库='GUN_SINGLE'` ×78；`csv='NONE'`/`库='GUN_SINGLE'` ×91 | CSV |
| `scatter_pattern` | 18 | `210101103`（光束喷枪，模式**单发散射**）：CSV `SCATTERS` / 库 `NORMAL` | **CSV**（散射武器却写 NORMAL 是错） |
| `lockon_mode` | 17 | `212301107`（光束加农）：CSV `LOCKON` / 库 `NONE` | CSV（维基「锁定」列非空 ⇒ 可锁定） |
| `weapon_category` | 14 | `210005101`（**米加·光束步枪**）：CSV `BEAM` / 库 `MACHINEGUN`；`214802001`（**指挥官专用光束机枪**）：CSV `MACHINEGUN` / 库 `WRESTLE` | CSV（库把机枪判成格斗） |
| `weapon_attribute` | 8 | `10020101`（グレネイド）：CSV `SOLID` / 库 空 | CSV |
| `equip_slot_type` | 7 | `214802001`：CSV `ONEHAND`(随类别) / 库 `TWOHAND`（随"格斗"） | CSV（同 `weapon_category` 的连带错） |

判据三条，互相独立且都指向 CSV：

1. **枚举自洽**：`cfg_schema.json` 里 `damage_attribute` 的 `enum_values` 是
   `NONE/SHIELD/GUN_SINGLE/GUN_RAPID/…/DAMAGE_FIELD_GUN`（29 值），`scatter_pattern` 是
   `NORMAL/SCATTERS/…`，`weapon_category` 是 52 值 `MACHINEGUN/SHOTGUN/…` ——
   **种子 CSV 的取值全在这些枚举内且语义对**（`光束喷枪`→`SCATTERS`、`光束机枪`→`MACHINEGUN`）。
2. **名称/维基自证**：C 组最刺眼的两条，CSV 与**武器名**和**维基「类别」列**一致，库相矛盾
   （`指挥官专用光束机枪` = 机枪，库却写 `WRESTLE` 格斗；`米加·光束步枪` = 光束，库却写 `MACHINEGUN`）。
3. **无人写它**：全仓 grep `scatter_pattern|lockon_mode|weapon_attribute|damage_attribute|equip_slot_type`
   的**写库**语句，只有 `load_paired_ms_db.py` 写 `equip_slot_type`/`weapon_category`；
   其余四列**当前没有任何脚本写库** ⇒ 库里的值是**更早某次生成/回灌的快照**，
   而"7 键只在 CSV、0 键只在库"证明**库更旧**。

⇒ **C 组：种子 CSV（当前 `gen_weapon_tables_wiki.py` 的产物）权威，方向 CSV → 库。**

> 注：这条与 A 组方向相反、与 B 组方向相同 —— 因为 `#37` 里**同样混着两个 id 家族**
> （与 `#36` §6.4 同构）。审计必须**按族拆**，否则会得出"CSV 全对"或"库全对"的错误结论。

## 9. ★★回答"资源特效应该跟 ID 绑定"——**对，客户端就是按 ID 算出来的**（2026-10-05 第四轮）

> 你的直觉：*"按理资源特效这种应该是跟 ID 绑定，不应该我们再指定吧，除非一些特殊的机体。"*
> **取证结论：完全成立。** `#37` 从头到尾**没有**要求我们指定任何特效/音效资源名。

### 9.1 客户端有两条 FX 路径构造器，都是"ID → 路径"

| 构造器 | 格式串（VA） | 输入 | 用途 |
|---|---|---|---|
| 数值型 | `fx/%02d/PP_%02d_%03d_%02d.vra`（`0xD6B1A4`，唯一引用 `sub_4828B0`） | 一个**打包十进制 ID** `a2` | 武器/弹丸侧特效 |
| 字符串型 | `fx/%02d/PP_%s.vra`（`0xED756C`，唯一引用 `sub_AB7A40`） | `fx_objects` 配置里的 `id` 字段 | 场景/机关类特效（`CPrjFxObject`） |

数值型展开式（`sub_4828B0` 内联）：

```c
sub_CC7064(v22, "fx/%02d/PP_%02d_%03d_%02d.vra",
    a2 / 100000 % 100, a2 / 100000 % 100, a2 / 100 % 1000, a2 % 100);
// a2 = 500803  ⇒  fx/05/PP_05_008_03.vra
```

⇒ **FX = 一个 7 位十进制 ID 的纯算术函数**，`CC NNN II`（类别 / 序号 / 变体）。
`fx.csv`（62 张本地表之一）里的 `ユニークＩＤ` 是**另一套小的共用编号**（1,2,3,1033…），
与上面这个 ID **不是同一个域** —— 所以"拿武器号去 fx.csv 查"必然 0 命中（这正是 §7 的坑）。

### 9.2 这条 ID 挂在实体上，由代码 set，不由表列 set

- `sub_440A10(entity, fx_id, flag)` = setter：写 `entity+115380`，然后**广播**给
  `dword_11E3F94` 注册表里所有同类实体（每个都调 `sub_4828B0`）。
- `sub_43FDA0` / `sub_4456A0` 是它的 getter/刷新壳。
- setter 只被一个虚表槽（`0xEED8CC` 一族 `sub_BA93xx`）调用 ⇒ 调用方是引擎侧视觉对象。

### 9.3 表里唯一的"显式 FX 路径列"只有一个（= 你说的"特殊机体"逃生口）

- `#DAMAGE_FIELD_PARAM`.col13 的物理列名就是 **`fx_resource`**（`cfg_schema` 里写作"FX 资源路径窄串"）。
- **真库 64/64 行全空** ⇒ 当前没有任何一把武器走"显式指定 FX 路径"这条支路；
