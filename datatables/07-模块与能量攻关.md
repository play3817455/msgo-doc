## 1. 编队COST 上限 —— 服务端主动推 `0xC0C4`

### 1.1 真因

**上限不是 `pilot_detail` 的字段**（早期两轮误判 ✗），而是客户端按"累积点/军衔"算档位、
由**服务端主动推送**喂进去的。我们从来没推 ⇒ 分母恒 0。

### 1.2 报文定义（反汇编实证 ✓）

- **消息 id**：`0xC0C4`（`recv_deckcost_update_by_accum_point`）
  - 依据：dispatcher `sub_B51930` 里 `0xB773BE  cmp eax, 0C0C4h ; jz loc_B77696`
- **体长 = 7 × u32 = 28B**（客户端末尾有"游标恰到底"检查 ⇒ 多一少一整包丢 ✗）
- **字段顺序**（按处理体 `0xB77696`~`0xB779D3` 的**日志语句顺序**逐字对齐 ✓）：

| 序 | 字段 | 说明 |
|---|---|---|
| 1 | `userid` | 客户端不校验 |
| 2 | `pilot_id` | |
| 3 | `accum_point` | 累积点 |
| 4 | `rank` | 军衔（界面 `BANK` 显示的就是它） |
| 5 | `base_accump` | 基础累积点 |
| 6 | `req_accump` | 下档需求（界面 `NEXT = req_accump - accum_point`） |
| 7 | **`deckcost`** | **★ 编队COST 上限（界面那个分母）** |

- **门禁**：入口 `sub_B41120(0x28)` + 出口 `sub_B41110(0x28)` ⇒ **通知 id = `0x28`**
- **末段**：`00B779E6 mov edx,[edx+0C0h] ; call edx` ⇒ `vt[0xC0]` 一次吃 7 个参数

### 1.3 去向（4 层 thunk 之后的真身）

```
vt[0xC0] = sub_BAB320 → sub_AF7920 → sub_42EEA0      （真身）
          ↑ 0xAF7941: mov ecx, dword_11E3EA8          ⇒ this = dword_11E3EA8
```

```c
// sub_42EEA0(this, a2=userid, a3=pilot_id, a4=accum_point,
//            a5=rank, a6=base_accump, a7=req_accump, a8=deckcost)
v9 = this[113769];                                     // 旧 rank
if ( a5 > v9 ) sub_62C160(v9, a5, this[113766], a7);   // ★上限变大 ⇒ 发 0x20000 事件刷新界面
this[113766] = a8;            // ★★★ deckcost = 界面"上限"
this[498]=a4; this[113768]=a4;  // accum_point
this[499]=a5; this[113769]=a5;  // rank
this[500]=a6; this[113770]=a6;  // base_accump
this[501]=a7; this[113771]=a7;  // req_accump
```

**★ 关键**：`dword_11E3EA8` 是"编队/机库管理器"（与 `sub_5FD020` 取**分子** `+415452` 数组同一对象 ✓）。
`app`（`dword_1201A60`，`CGVOProtoLounge`）只有 `0x8378` 字节，**装不下 `+0x6F1D8`** ⇒ 别搞混 ✗。

### 1.4 踩过的坑：**第一次推必被丢**

P248 只在 `0x16AC msma_init_get` 应答后推**一次** ⇒ x64dbg 现场读
`dword_11E3EA8 + 0x6F1D8` 仍是**未初始化堆标记**（`0xBAADF00D`/垃圾值）⇒ `sub_42EEA0` 没执行 ✗
⇒ 原因是**入口门禁 `sub_B41120(0x28)` 那一刻 `0x28` 号通知还没注册** ⇒ 整条静默丢弃。

**修法**：**周期性重推**（挂在已有 10s CPS 心跳上）。
**安全性有铁证**：`if (a5 > v9)` 守卫 ⇒ **同值重复推不会重复触发界面刷新** ✓

### 1.5 服务端实现位置

- `protocol/lounge_pilot_extra.go`：`MsgDeckcostUpdateByAccumPoint = 0xC0C4`、`DeckcostUpdateBodyLen = 28`、
  `EncodeDeckcostUpdateByAccumPoint(7×u32)`（用 `AppendID`，**不是** `EncodeChannelSkeletonR` ✗）
- `authsrv/pilot_extra.go`：`deckCostCap = 1000`、`deckcostAccumPoint = 27`、`deckcostRank = 1`、`deckcostReqAccump = 30`
- `authsrv/server.go`：① `0x16AC` 应答后推一次 ② `startCpsTicker` 里每 10s 重推

### 2.3 ★P250 的那 4 行**曾经又被弄丢**，以及最终口径（2026-09-28 深夜结案）

P250 是**直接补在产物 CSV 上**的手术。后来 `msma_battle_detail.csv` 改成由
`datatables/gen_msma_machine.py` 整表重生成，而那个生成器**只发 7 个属性**
⇒ **`ENERGY` 又没了**（连带 `BOOST_SPEED`/`JUMP`），且没人发现 —— 直到
`server/internal/datafiles/battle_detail_test.go` 的 `BOOST_SPEED` 守卫测试变红 ✗。

本轮按反汇编把三项**逐一结案**（详见 `04-填充日志.md` §14）：

| 属性 | 最终处置 | 值 | 依据 |
|---|---|---|---|
| `ENERGY` | ★**发**（`<id>,1000`） | 常量 1000 | 与 P250 同值；客户端 `sub_581690` 钳到 99 ⇒ 1000/99 等价 |
| `BOOST_SPEED` | ★**发**（`<id>,0.840000`） | 常量 **0.84** | 面板最高速度 = `MOVE × max(+260,+276) × 1.1904762` ⇒ `1/1.1904762 = 0.84` |
| `JUMP` | ✗**不发** | — | 无面板绑定、无来源 ⇒ 「不猜」（缺行 = 全 0，与现状一致） |

> ⛔ **`BOOST_SPEED` 绝不能写 1000/1900 这类数值**（P250 当时写的 `1000` 就是这个错）：
> 它会被当**速度倍率**乘进面板 ⇒ 面板「最高速度」显示成百万级（用户实测截图 2777619 ✗）。
> 正解是 **0.84**（乘上常量后 = 1.0 ⇒ 面板显示 == MOVE ✓）。

**教训**：属性长表由生成器整表重生成时，**曾经手工补过的行必须有守卫测试兜住**，
否则下一次重生成就会静默回退 ✗ —— 现在由 `battle_detail_test.go` 的三条测试负责
（`BOOST_SPEED` 值域 + `ENERGY` 行存在/键覆盖 + **10 个槽键 ↔ 明细行两表不变量**）。

## 4.4 ★★★★★★★武器槽空的真因：**查表键是"モデルID"（`+0x1B4`），不是練度ID**

### 4.4.1 铁证（`sub_581690` 反汇编）

```asm
005816AC  lea eax, [ebp+1B4h]      ← ★★★ 键 = 机体对象 + 0x1B4
005816B7  add esi, 4
005816BE  call sub_581270          ← 用这个键查 MSMA_WEAPONSET
005816C3  mov eax, [esp+18h+arg_0]
005816C7  cmp eax, [esi+8]         ; 与 end 比较（未命中 ⇒ 走 0 填充）
005816CC  lea esi, [eax+28h]       ; 命中 ⇒ 行数据 = 节点 + 0x28（88B 行结构 ✓）
005816D3  lea edi, [ebp+0C0h]      ; 拷进机体对象 +0xC0（11 dword = 44B）
005816DE  rep movsd
005816E2  ... sub_CC6510(0x2C)     ; 未命中 ⇒ 把 +0xC0 起 44B 清零
005816F4  mov esi, dword_11EBA64
005816FA  lea eax, [ebp+1D0h]  …   ; 后面几组同理（+0x1D0 / +0x1EC / +0x208 …）
```

而 `CHARA_MODEL`（`msma/msma_model.csv`）文档明写：

> **列 71 / 72 = モデルID 低32 / 高32（`+1B4h` / `+1B8h`）** ★

⇒ **`+0x1B4` 就是 モデルID 低 32 位** ⇒ **`MSMA_WEAPONSET` 的 col0 必须是 モデルID（9 位）** ✓✓✓
