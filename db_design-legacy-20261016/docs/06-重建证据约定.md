# 功能重建的证据约定

更新：2026-10-06。用户授权数据库、serverv 与本资料库按取证结果覆盖重写。

执行路线见 [客户端功能恢复路线图](../../serverv/docs/06-功能恢复路线图.md)，进度见 [执行账本](../../serverv/docs/reconstruction-progress.json)。

原始来源仅为目标版本客户端汇编、解包资源与 gow_wiki 原文。机体/武器数值以 wiki 为唯一来源；资源身份以实际文件和读取逻辑复核；协议及行为以同版本 EXE 取证。此库和 protocol_analysis 是派生资料，允许纠正，不能相互引用作为独立证据。

每个重要结论应包含：结论标识、功能场景、目标 EXE/IDB/资源版本、来源文件/页面/地址、直接观察、推导过程、冲突、结论种类、实现引用、回归结果及客户端验收。种类分为已取证、推断、兼容策略、未知；不得把实现策略升级为原服事实。

尤其区分 wire 字段、客户端内存布局、内部数据库字段；区分定义键、实例键、归属寻址键、资源键与预设标识。数据库可为业务增加结构，不能只复制线模型或按相似字段名归并所有权。

现有合成武器键是待审候选，可能需要替换或重建。缺少同名 DDS 不是原服 ID 关系的证据；图标存在、代码查表成功也不能证明变体及数值正确。ID 的编码/分类/分支使用未完成取证前，不扩充合成定义。

修改当前模型时同步源说明、生成器与生成物；历史证据保留版本并标记被取代的结论。已有 DONE、代码注册和往返测试只记录其验证范围；功能完成以真实客户端场景为准。

原服专有信息无法恢复时，明确采用本服兼容策略、适用范围与验证结果；无需等到恢复原服全部内部细节才推进下一项可验证工作。

## 全玩法范围

用户确认需恢复目标客户端的全部玩法；登录至基础战斗链只优先。玩法索引见 `serverv/docs/gameplay-inventory.json`，现有命令名仅作派生发现索引，需要补入口、同版本汇编、数据和真实客户端验收。无 CS、未归类或缺少原服服务的玩法也保留工作项，兼容实现单独记录；不可用不能自动等同于范围外或已完成。
