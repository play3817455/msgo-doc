# 配置表 79 张 · 列定案专案

## 目标

把 `datatables/01-列注释/` 中 79 张配置表每一列的**用途**与**订案字段名**整理成机器可读 schema，供：

1. **db_design 静态站** — 与协议库表设计并列查阅（`site/cfg/`）
2. **GM 后台** — 表头显示 `订案名 + 中文语义`，不再只有 `col0/col1`
3. **后续 cfgload 迁移** — 物理列从 `colN` 改为语义名（第二阶段）

## 数量口径

| 口径 | 数量 | 说明 |
|------|------|------|
| datatables 专案全集 | **79** | 76 下发 + 3 本地 + AUTOEXEC 脚本 |
| `meta.cfg_manifest` | **76** | 客户端 0xF86A 下发清单（含空 CSV 占位） |
| `cfg` schema 物理表 | **~70** | 有 CSV 内容且 cfgload 建表的才会出现 |
| GM 下拉列表 | **≥76** | manifest + schema 中未建表的补全（0 行 · 仅列定义） |

本地 3 张：`LVUP_MSMA`、`MSMA_MATERIAL`、`BGMPACKAGE`（不下发，服务端/工具用）。

## 产物路径

```
datatables/01-列注释/*.md     # 人工/IDA 证据源（只读参考）
db_design/schema/cfg/
  index.json                  # 79 表索引
  tables/{TABLE}.json         # 每表列定案
db_design/site/cfg/           # 静态 HTML（build_site.py 生成）
serverv/static/cfg_schema.json  # GM 运行时读取
```

## 字段约定

每列 JSON：

| 字段 | 含义 |
|------|------|
| `csv_index` | CSV 0-based 列号 |
| `db_column` | 当前 PostgreSQL 列名（`colN`） |
| `name` | **订案字段名**（英文 snake_case，GM 表头主显示） |
| `display_name` | 中文摘要 |
| `type` | u32 / str / enum / float … |
| `status` | `confirmed` / `partial` / `pending` / `gap` |
| `meaning` | 原文语义（含 IDA 置信度标记） |

`gap` = CSV 有列位但读表函数未单独取证（默认 0）。

## 维护流程

1. 更新 `datatables/01-列注释/{表}.md`
2. `python db_design/tools/import_cfg_columns.py`
3. `python db_design/tools/build_site.py`
4. 重启 msgoser（或 gmd）以加载新 `cfg_schema.json`
