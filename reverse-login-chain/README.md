## 一、为什么要独立建这个工作区

现有知识库（`.codebuddy\memory\topics\`、`研究知识库.md`、`已验证知识库.md`）是**按主题/按时间**记录的，
适合"查某条结论"，但不适合"系统性地把一条链路补完"。本工作区改为**按节点流水线**推进：

- 一次只做一个节点；
- 每个节点有**明确的产出文档**（`nodes/NN-*.md`）和**完成判据**；
- 完成的节点写回知识库（`topics/08`、`topics/10` 等）并在这里留档；
- **每完成一个节点，自动创建下一个节点的自动化任务**（链式推进，见 §四）。

## 二、总体边界

```
起点：主窗口出现 → 登录界面 → 用户输入账号/密码 → 点【登录】
终点：客户端进入游戏大厅（lounge 首屏，可交互，不再白屏/转圈）
```

沿途要研究透的三类东西（每个节点都要覆盖）：

| 类别 | 含义 | 归档位置 |
|---|---|---|
| **汇编逻辑** | 该节点涉及的函数地址、调用链、分支条件、数据结构偏移 | 节点文档「汇编逻辑」节 |
| **状态机** | 该节点的状态字段/取值/迁移条件/驱动 tick | 节点文档「状态机」节 |
| **文件与格式** | 该节点读写的本地文件、网络报文、资源格式（含字节级布局） | 节点文档「文件与格式」节 + `formats/` |

## 四、自动化任务机制（链式推进）

**核心规则**：一个节点 = 一个自动化任务。任务完成该节点后，**自动创建下一个节点的任务**。

```
[节点 N 的任务] --(完成)--> 写 nodes/NN-*.md + 回写知识库
                          --> 更新 progress.json（N 置 completed，currentNode 指向 N+1）
                          --> 用 automation_update 创建【节点 N+1】的一次性任务
                          --> 追加记录到 automation/tasks.json 与 automation/runs.log
```

- **任务 prompt 全部预置**在 `automation/prompts/node-01.md … node-09.md`，
  公共规则在 `automation/prompts/common.md`。任务 prompt 本身很短，只要求「读 common.md + node-NN.md 并严格执行」。
- **一次性任务（scheduleType=once）**，间隔 20 分钟；每条设 `maxDurationMinutes: 90` 防止跑飞。
- **断链自愈**：任何任务开头必须先读 `progress.json`；若发现「当前节点已完成但下一个节点没有任务」，
  直接补建下一个节点的任务（见 common.md §5）。
- **进度真相源**：`progress.json`。任务只认它，不靠对话记忆。

**手动干预**（随时可用）：

```
# 查看进度
cat  f:\9ymsgo\9you\reverse-login-chain\progress.json
# 重置某节点为 pending，让任务重跑
#   编辑 progress.json：nodes[i].status = "pending"，把 currentNode 改成它
# 立即触发下一次研究：在该工作区对 Codebuddy 说「按 automation/prompts/common.md 执行当前节点」
```
