## 0. 一句话结论

世界选择→大厅跳转由 **3 对报文** 驱动，本轮把 N5 三个空白补成逐字段：

## 4. OTP 全生命周期（四点闭环，★本轮定案）

| 环节 | 发生处 | 结论 | 证据 |
|---|---|---|---|
| **① 生成** | 服务端 | 客户端**无任何 otp 生成逻辑**（全 IDB 无 otp 的哈希/随机/格式校验） | 客户端侧仅见 `sub_CC65C6` 拷贝 + `sub_B02B40` 回写 |
| **② 下发** | `0x1146`（30000） | `sub_439030` 把 `otp` 拷到 `app+1297`（41B 容量，拷 40B） | `sub_CC65C6(this+1297, 41, a7, 40)` |
| **③ 回传** | `0xF24B`（30001） | FSM state20 `sub_43E660` → `sub_42D3D0(app+1168, app+1297, app[1340])` 把 otp 转存 `step+149` → case2 `sub_BAAF60(userid, step+149)` → `sub_B896A0` 组 `u32 userid + NUL串 otp` | `sub_42D3D0` / `sub_B896A0` |
| **④ 校验** | 服务端（0xA5DA 回包） | 客户端**不在本地校验 otp**；"校验"等价物 = 服务端比对 otp 后回 `0xA5DA` `result+admin_lv`，客户端据 `result` 决定 state 3→4（成功）或回登录窗口（失败） | `sub_439220` / `sub_430E10` |

- ★ 私服落地：三方一致即可——`0x1146` 下发、`0xF24B` 回传、N8 `0xFB85` 再下发**同一个值**；推荐空串 `\0`（回传体变 `u32 userid + 00` = 5B）。
- 客户端对 otp 的三种动作：**存（`app+1297`）→ 转存（`step+149`）→ 原样回写（`0xF24B`）**，无计算无校验。

3. ◐ `channeling_type`（0xA380 第 3 字段）取值**已定 0..3**（`dword_1104680`，`sub_A1E880` 返回；`0xA28F04` 循环 `cmp esi,4; jl`，对应 4×28B 线路串）；⚠️ 但 4 个线路**各自的具体语义**（频道/线路名）仍在 UI 层未展开——影响 N6/N7。
4. ⚠️ `sub_43EE50` 中 `v41=icon_id`、`v32=负载等级` 赋值后未在反编译片段内看到显式写入 `v31`（疑经 `sub_433050` 初始化 + 内联写入被 IDA 折叠），窗口条目 72B 完整布局未逐字节（属 UI 结构，非线上格式）。

## 6. 对服务端落地的影响

- ★ **309B 世界条目造包铁律**（`0x298E`）：
  - 字段顺序 = `worldid(4) + name(49) + name_en(49) + desc(193) + stat(4) + icon_id(2) + client_now(4) + client_max(4)`，**全定长**，短串补 0x00。
  - ★ `client_max` **必须非零**（否则客户端算 `100*now/max` 除零崩溃）；`client_now ≤ client_max` 更真实。
  - `count ≤ 32`；`last_world` = 上次登录世界（可等于列表内某 worldid 以触发预选）。
- ★ **OTP 闭环**：`0x1146` 下发的 otp 必须与 `0xF24B` 回传解析、N8 `0xFB85` 再下发**一致**；推荐空串。`0xA5DA`（lounge）必须回 **8B**（`result + admin_lv`），`result>=0` 才推进。
- ★ **Lounge step 结束**：`0xA5DA.result>=0` 后 case 4~0xA 是**纯本地初始化**（打开机师记录窗口、初始化子系统单例），无网络报文；case 0xA 置 `app[114201]=1` 后 step 结束，**下一阶段 N6（数据表下载）由另一条 step 链驱动**，服务端在此阶段只需保证 `0xA5DA` 正确即可。
- `0x4F3F` 回 `reset_sec=0` 最省事（避免倒计时框卡点）。
