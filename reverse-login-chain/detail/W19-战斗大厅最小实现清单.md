> 状态：✅ done ｜ 时间：2026-09-15 ｜ 会话序号：W19（第 19 个会话）｜ 证据来源：W15~W18 明细 + B01/B02/B03 战服取证（均为 IDA 反编译/反汇编，基址 `0x400000`）＋ 服务端现状（`server/internal/{authsrv,protocol}`）

## 0. 一句话结论

**「进入战斗大厅（可出击）」= 三个可验收判据**：
- **J1 进房间**：`0x61AF btlroom_enter` → 服务端回 `0x5383`（含真实 `battlesv_host/port/otp_battle`）→ 客户端建 `CGameStateStepUpdateLoginBattle` 并**主动新连战斗服**；
- **J2 战斗服会话**：第 3 条 TCP + 复用 N3 access 握手 → `0x34A9/0xDE24` → `0xF24B`(battle 变体)/`0xA5DA`(20 字段) → 客户端 `sub_448FE0` 战场会话初始化成功；
- **J3 进战场**：`0x1365 game_begin`(23 字段) → 客户端可 `msma_spawn_*` 出击。

**服务端现状**：30000/30001/30002 已实现；**战斗服（第 3 条连接）与出击族真实应答均未实现**——目前用「挂 `0xB681` 后硬推 `0x5383`(host=127.0.0.1, port=30002)」的 hack 顶替，它只让客户端"开了大厅窗口"，**并没有真正建战斗服会话**。要"可出击"必须补两件事：① 大厅侧出击族应答（房间列表/建房/进房给真实战斗服凭据）；② 战斗服第三条监听 + `0xF24B→0xA5DA→0x1365`。

## 1. 判据链（「到战斗大厅」的完整里程碑）

```

用户点出击 CMainMenuWindow(#103)                                       ↑ 客户端主动 connect(host,port)
  → btlroom_get(0x7ABC, room_type)  ──► 0x244E info_one×N + 0xB0A3    │   （sub_AF7130，与 auth/lounge 同一 helper）
  → 选房 btlroom_enter(0x61AF)      ──► 0x5383 battlesv 凭据 ──────────┘
  → sub_442970 建 LoginBattle（vtable 0xD68474）
  → tick sub_440080: state0 连 / state1 等就绪 / state2 发首包
                                                        ├─► 0x34A9 proto_version_check ──► 0xDE24(12B)
                                                        ├─► 0xF24B authenticate(battle 变体) ──► 0xA5DA(20字段,630+len(room_name))
                                                        └─► 0x1365 game_begin(23字段) → 可出击
```

| 判据 | 触发 | 判定通过的标准 | 未通过的失败现象 | 证据 |
|---|---|---|---|---|
| **J1 进房间** | `0x61AF btlroom_enter` 请求 | `0x5383` 回 `result≥0` + `battlesv_host`(NUL≤128) + `battlesv_port` + `room_id` + `otp_battle`(NUL≤40) | 回错/不回 ⇒ 客户端不建 LoginBattle、**永远进不了战斗服**（卡进房作业） | W15 §2.3 / W17 §3.3.1 |

## 3. 关键报文逐字段表（★核心）

> 约定：`+0` 起 = 报文头 2B ID 之后（体）。读取器宽度：`sub_B02DD0`=u32｜`sub_B02DF0`=u16｜`sub_B06230`=u8｜`sub_B02BA0`=NUL 有界串（cap 参数）。

### 3.1 `0x5383` btlroom_enter_r（S→C，★进战斗服凭据，J1 命门）

> ⚠️⚠️ **字段序存在两种解读（冲突待复核）**：
> - **W17 §3.3.1（静态）**：`result u32 | matching_type u32 | battlesv_host NUL≤128 | battlesv_port u32 | room_id u32 | otp_battle NUL≤40`（6 字段，`vt[0x78](0xBA=186)`）。
> - **lounge_channel.go::EncodeBtlroomEnterR（真机实测）**：`battlesv_port u32 | room_id u32 | battlesv_host NUL≤128 | otp_battle NUL≤40`（4 字段，无 result/matching_type），并实测「host 放最前 ⇒ 客户端把 `127.` 当 port ⇒ 连不上」。
> - **裁决建议**：真机验证优先 ⇒ 实现按 `port → room_id → host → otp` 序（host 在第 3 位）；W17 的 `result/matching_type` 前缀若存在，客户端是 `result≥0` 有符号判定，把前 2 个 u32 填 0 即可同时兼容两种解读。**落地前建议重读 case `0xB616DC` 一次定序**（W20 冲突消解项）。

| 偏移 | 类型 | 长度 | 含义 | 取值域 | 数据来源 | 必须非零 |

| +0 | u32 | 4 | battlesv_port（★第 1 读，实测口径） | 0..65535 | 战斗服监听端口 | **是** |
| +4 | u32 | 4 | room_id（★第 2 读） | 回显 | 房间表 room_id | 否 |

## 5. 失败现象对照表（漏实现/实现错 → 客户端症状）

| 服务端漏/错 | 客户端现象 | 根因 |
|---|---|---|
| 不回 `0x244E`+`0xB0A3`（btlroom_get） | 房间列表空白、无法选房、点出击无房间 | `btlroom_get` 无 `_r`，房间 UI 靠这两条驱动 |
| `0x5383` 回错字段序 / 不回 | **进房间后客户端不建 LoginBattle、进不了战斗服** | 字段序错 ⇒ host/port 解析错位；不回 ⇒ 进房作业停在 result 判空 |
| `0x5383` 的 `battlesv_port` 指向一个没监听战斗服的端口 | 客户端 connect 失败、反复重连、卡加载 | 战斗服第 3 条连接未起 |
| `0xA5DA` 回错（字段缺/体长错/result<0） | 战场加载黑屏、`sub_448FE0` 后状态机不成立 | `0xA5DA` 是战场会话初始化入口，20 字段必须齐 |
| `0x1365` 回错 | 战场起不来、**无法出击**（无 spawn） | `game_begin` 23 字段是出击前置 |
| 战斗服不复用 N3 握手 | 客户端握手失败、直接断连 | battle 协议对象 `vt[8]=sub_C84B60` = N3 帧层 |
| 出击族其余应答（invite/party/xwar）零填但不回 | 对应 UI 功能卡住（不影响进房主链） | 无「必须非零」字段，但体长必须精确 |

## 6. 对服务端落地的影响（下一步 + 缺口清单）

1. **★当前 hack 必须升级**：`authsrv/server.go` 里挂 `0xB681` 推 `0x5383`（host=127.0.0.1, port=30002）只让客户端"开大厅窗口"，`battlesv_port=30002` 指向的是 **channel 频道服而非战斗服** ⇒ 客户端连的"战斗服"实际还是 lounge 协议对象，**J2 从未真正达成**。落地应：
   - 大厅侧：真正实现出击族（`btlroom_get` 房间列表 + `btlroom_enter` 回真实战斗服凭据），去掉硬推；
   - 战斗服：新增独立端口监听（如 `:30003`）+ `CGVOProtoBattle` 协议对象（0xF24B battle 变体 / 0xA5DA / 0x1365），复用 `internal/ivce` 握手与 `internal/conn` 会话层。
2. **复用清单**（别重造）：iVCE 帧层 + Camellia（`internal/ivce`）、access 握手、`Registry` 分发器、`Session` 会话对象、`otp` 票据、`store` 数据访问——战斗服第 3 条连接全部可复用，只差"battle 报文表"。
3. **config 扩项**：`battle.addr`（战斗服监听）、`battle.mission/map`（任务/地图参数）、房间表存储。
