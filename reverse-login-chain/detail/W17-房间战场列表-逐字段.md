## 6. 对服务端落地的影响

1. **★`btlroom_get` 不能回 `btlroom_get_r`**（不存在）：实现房间列表 = 连发 `0x244E`(每房间 1 条) + `0xB0A3`(收尾)，客户端据此刷新房间 UI。
2. **★`btlroom_enter_r`(0x5383) 是进战斗服的唯一通道**：必须回 `result≥0` + `battlesv_host`(NUL≤128) + `battlesv_port` + `room_id` + `otp_battle`(NUL≤40)；回对后客户端建 LoginBattle 连战斗服（W18 的 host/port 来源）。
3. **roominfo 结构**（16 字段，含 73B 定长名 + 25B NUL 名 + 2×11B clan）是房间/coop/member_detail 三处复用的核心，服务端造房间列表必须按此 16 字段序。
4. **party 招募列表** = recruits(80B 线/84B 内存) + leaders(58B 线/64B 内存)，两数组 ≤200。
5. 其余出击/party/xwar 应答体可按 §4 骨架零填推进（无「必须非零」字段），仅 enter_r 的战斗服凭据需真值。
6. 门序号三重互证「接收门 = 发送通知索引 + 1」在出击族 9 条上全部命中（见 §1.2），服务端 push 应答无需额外登记门位。
