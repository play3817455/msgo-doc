# B07/B08 · 开火 / 命中 / 伤害 / 死亡 / 得分 族取证

> 2026-09-15。数据来源：`formats/battle-交互总表.md`（S5/S6/S7 段）+ IDA 实测（`sub_B3B7A0` 等）。
> **用途**：这是"打得起来"的最后一环 —— 上行"我打了谁"，下行"谁掉血/谁死了/加多少分"。

## 1. ★架构结论：普通射击**不广播**，靠本地弹道 + 命中上报

| 模式 | 上行（C→S） | 下行（S→C） | 说明 |
|---|---|---|---|
| **普通射击**（单发/连发） | `weapon_fire__shot_single`(0x7CA0)、`shot_rapid`(0xA404) | **无**（recv 表里查无此二 ID ✓） | 各客户端**本地模拟弹道**；命中用 `weapon_hit_to`(**0x770D**) 上报 |
| 特殊武器 | `grenade / hand_throw / air_bomb / snipe_beam / bit / bit_reflect / deploy_arms / damage_field / start_homing / wrestle / funnel / for_myself / shot_single_special …` | **各有 `_r` 孪生**（服务端转发放大给所有人看特效） | 需要服务端裁决/同步 |

⇒ **服务端的核心输入只有 `weapon_hit_to`**；输出是"伤害结果面"（§3）。
⇒ 这解释了为什么客户端到战服最重的是 `weapon_hit_to` + 快照，而不是射击包。

## 2. ★上行 `weapon_hit_to`(0x770D) 精确线布局（`sub_B3B7A0` byte-exact）

```
+0    u16   id = 0x770D          ← ★C→S 的 body 首 2 字节就是报文 ID（写包时 `*(_WORD*)p = 30477`）
+2    u64   phash                ← 由 a2(低32)+a3(高32) 打印（`sub_B08500`）
+10   u32   frame_count
+14   u32   weapon_itemid
+18   u32   fire_id
+22   ── 8 个数组，依次（每个 = u32 count(≤16) + count × u16）：
        ent_ids[]  hit_pos_x[]  hit_pos_y[]  hit_pos_z[]
        hit_dirs[]  hit_distance[]  body_distance[]  body_regions[]
+?    u8    charge_lv
+?    u16   AI_ent_id
+?    u16   instate_from_ent_id
+?    u32   create_frame_count
+?    u8    is_down_range
+?    u8    is_wrestle_first_high_lockon
```
- 写包原语：`sub_B02D80`=u32(+4)、`sub_B02DA0`=u16(+2)、`sub_B061C0`=u8(+1)（均已反汇编确认）。
- **自洽校验**：总长 = `2 + 8 + 4+4+4 + 8×(4+2N) + 11 = 65 + 16N`；N≤16 ⇒ 最大 **321B**；
  而发送缓冲 `alloc = 334`（`vt+120(334)`）✓✓ **完全吻合**。
- ⇒ 服务端解析器：**跳过/校验首 2 字节 ID**，然后按上表读（每数组自带 count，最多 16 个命中目标）。
- ⇒ 与 B06 结论一致：**包里没有任何 damage/hp 字段**（伤害由服务端算）。

## 4. ★服务端"信任式结算"流水线（建议直接照此实现）

```
收到 C→S weapon_hit_to(0x770D)   // 校验首 2 字节 = 0x770D；解析 8 个数组（≤16 目标）
  for k in 0..N-1:
      atk = AI_ent_id ?: 由 AI_ent_id 解析出的实体（否则 = 发送者的实体）
      tgt = ent_ids[k]；body_region = body_regions[k]
      ① 查武器数据：weapon_battle_detail.csv 的 POWER（回复类取负）、RANGE、RATE…
      ② 结算：dmg = f(POWER, charge_lv, 属性(MS_* 与武器属性), body_region 部位系数,
                     damage_rate(A/B 由 sub_4419F0 下发的那两个值), hp/shield 当前值)
      ③ 广播 S→C：
         weapon_hit_from(0x49C6)   // 含 hp_now/hp_max/damage —— 所有人（或仅当事双方）
         shield_any_damage(0xF4D7) // 走盾时补发
         weapon_hit_to_r(0xDDF7)   // 给射手（回执/命中特效）
         entity_msma_show_hp(0xE4DB)// 可选（血量条）
          若 hp<=0:
             entity_msma_dead(0x9105)         // 28B（含 kill_streak/decal/is_resurrect）
             kill_count_update(0x844B)        // 23B
             score_update(0x8D59)             // 28B（射手加分）
             msma_spawn_wait_update(0x8DE4)   // 重生等待（见 B05）
  另：摔跤/翻滚等硬直补发 weapon_hit_from_with_stumble/tumble/staggery(16B)；
      模块被击破补发 weapon_hit_from_with_module(7B)。
```
**公式口径可自定义**（客户端不参与结算），但**必须有**：`hp_now/hp_max/damage` 是客户端 UI 唯一的伤害来源。
