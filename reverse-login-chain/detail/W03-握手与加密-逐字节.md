## 0 一句话结论

TCP 之上是 **iVCE 传输层**：先 **裸字节**密钥交换（C→S **16B** = 客户端 RSA 模数 `n_C`，S→C **32B** = 两块 RSA 密文），
之后全部流量 = **4B 小端「明文长度 n」头 + 16B×N 密文（Camellia-128 变体，计数器加在 ctx[0] 即第 1 个白化子密钥）**。
★ 本轮新增：**单帧上限 16366B 的三个独立证据点全部落实**；**接收/发送两侧的环偏移与错误码落实**；
**握手与加密阶段共用同一个输入环（+0x230）**；**`sub_CA3030` 在握手完成后的同一调用里接着做收包解密（sub_C88510）**；
**两套"孪生实现"定案 = 同一接口的两个算法档，由运行时工厂指针 `vce[677]` 选择**。
⇒ **服务端只需公钥运算 `pow(K, 65537, n_C)`**，`server/camellia128.py` + `access_sticky` 的原理正确（block2 必须 RSA）。

## 1 帧层（逐字节）

### 1.1 帧头 4B = 明文长度 n（✅ 本轮复核 `sub_C882F0`）

```
v2  = this[304] - this[303]          // 发送环待发明文字节数
cap = max(this[114]-18, 1400)        // = 16366（见 §1.2）
n   = min(v2, cap)                   // 本帧明文长度
v19 = this[302] + this[303]          // 明文起点
v20 = n;  sub_CAC660(&v20, 4)        // ★ 4B 小端 = n 本身
full = n >> 4 ; tail = n & 0xF
need = 4 + 16*full + (tail ? 16 : 0)
```

| 位域读法 | 值 |
|---|---|
| u32（LE）整体 | **n = 本帧明文字节数** |
| bit3..0 | `tail = n & 0xF`（尾块有效字节数，0 表示无尾块） |
| bit31..4 | `full = n >> 4`（完整 16B 块数） |

⇒ 两种写法**数值恒等**：`n == (full << 4) | tail`。
⇒ 服务端只需 `struct.pack('<I', n)`；若按"块数|尾"拼装结果相同（但语义必须理解成 n，否则游标算错）。

### 1.2 ★ 单帧明文上限 16366B（三处独立证据）

| 证据 | 位置 | 事实 |
|---|---|---|
| 常量来源 | `sub_CAFE90`（iSession ctor）`0xcaffbc` | `this[114] = 0x4000`（= 16384） |
| 上限函数 | `sub_C87F30` `0xc87f36` | `result = this[114] - 18; if (result < 1400) return 1400;` |
| 发送侧 clamp | `sub_C882F0` `0xc8832d` | `v5 = max(this[114]-18, 1400); if (n > v5) n = v5;` |
| 接收侧硬判 | `sub_C88510` `0xc88567` | `if (n > sub_C87F30(this) \|\| !n) break;` ⇒ 落到 `return sub_CAC820(13,5)` |

`0x4000 - 18 = 16366` ✅（`this[114]` 即 0x4000 ⇒ 上限 16366；不是 16384）
⇒ 发送侧是 **clamp（自动分帧）**、接收侧是 **硬判（关闭连接）**，两侧不对称 —— 服务端**必须**自己分帧。

### 1.3 尾块：补满整块 + 随机填充（✅ 本轮复核）

`sub_C882F0` `0xc88443..`：尾块 16B 缓冲逐字节填：
- `i < tail` ⇒ 取明文第 `16*full + i` 字节；
- `i >= tail` ⇒ `sub_CB09E0(sub_CAC640(this[19]))` 取随机字节。

★ **随机源 = MT19937**（`sub_CB09E0`：`this[624]` 索引、`this[623]` twist、`sub_CB0990(5489)` 默认种子、tempering 常量 `0xFF3A58AD`/`0xFFFFDF8C`/`>>18`）⇒ 非密码学安全，但**接收方丢弃尾块多余字节**（§1.4），故只影响指纹、不影响互通。

### 1.4 接收侧拆帧（✅ 本轮复核 `sub_C88510`）

```
v14  = 解密输入环可读长度（sub_CAC6A0）
if (v14 < 4) return 1                       // 等更多
loop:
  n    = LE32(环指针)
  if (n == 0 || n > 16366) → sub_CAC820(13,5)   // ★ 关连接（不是丢帧）
  full = n>>4 ; tail = n&0xF
  need = 4 + 16*full + (tail ? 16 : 0)          // v8
  if (v14 < need) return 1                      // 等更多
  输出环余量检查： v1[315] + cap - v1[316] < n → sub_CAC820(10,3)   // ★ 关连接
  full 块：sub_CB4AD0(128, in, &v1[232], tmp); ++v1[232]; 追加 16B   // 解密块 → 追加
  tail 块：sub_CB4AD0(...);           ++v1[232]; 追加 tail 字节      // ★ 多余字节丢弃
  sub_CAC6D0(need)                              // 消费整帧
  重新取可读长度；< 4 ⇒ return 1；否则继续循环    // ★ 一次调用可吃多帧
```

| 错误 | 码 | 现象 |
|---|---|---|
| 长度非法（0 或 >16366） | `sub_CAC820(13,5)` | 直接关连接（历史上"一过大表就掉线"） |
| 明文输出环余量不足 | `sub_CAC820(10,3)` | 直接关连接 |
| 数据不足 | `return 1` | 正常等下一批 |

## 2 握手（16B / 32B）

### 2.1 形态（✅）

- **握手段无 4B 帧头**，是裸字节；`sub_C9E810` 状态 2 直接 `sub_CAC660(buf, 16)` 投递。
- `sub_C9F820` 自己消费 16B（函数尾 `sub_CAC6D0(this[156] >> 3)`），`sub_CA11D0` 调用它两次 ⇒ **32B 恰好被两段各 16B 消费**（`sub_CA3030` 状态 3 只做"可读 ≥ 32B"的前置判断）。

### 2.2 Mode A（`+0x9C == 0`，**本客户端走这条**）逐字节（✅）

| 步骤 | 代码 | 字节 |
|---|---|---|
| 1 | `sub_C9E810` 状态 2：RSA ctx `vt[4]`(`sub_C8F9C0`) 导出 | `*a2 = ctx[6]; a2[1]=ctx[7]; a2[2]=ctx[8]; a2[3]=ctx[9]` ⇒ **n 的 4 个 dword 原样 = 16B** |
| 2 | `sub_CAC660(v16, 16)` | **C→S 16B**（小端 limb 序，实测与 `_rsa2.py` 穷举一致） |
| 3 | `sub_CA3030` 状态 3：可读 ≥ 32 ⇒ `sub_CA11D0` | S→C 32B 判定 |
| 4 | `sub_CA11D0` 第 1 段：`v9=128; sub_C9F820(&v9)` | 私钥模幂 → 16B `K_in` |
| 5 | `sub_CB4580(128, K_in, this+232)` | `K_in` → **`+0x3A0`（入站解密 ctx）** |
| 6 | `sub_CA11D0` 第 2 段：`v16=128; sub_C9F820(&v16)` | 私钥模幂 → 16B `K_out` |
| 7 | `sub_CB4580(128, K_out, this+164)` | `K_out` → **`+0x290`（出站加密 ctx）** |
| 8 | `sub_CA3030` → `+0x280 = 6`，返回前 `sub_C88510` | 进入加密收发 |

```
C→S : 16B  = n_C                       （无帧头）
S→C : 32B  = RSA_enc(K_in , n_C) ‖ RSA_enc(K_out, n_C)
之后 : 全部 = 4B LE(n) + 16B×ceil(n/16) 密文
```
⇒ **服务端义务**：`block1 = LE16(pow(K_in , 65537, n_C))`、`block2 = LE16(pow(K_out, 65537, n_C))`，
   **两块都必须是 RSA 密文**（`sub_CA11D0` 两次都调 `sub_C9F820`，函数内无任何旁路分支）——N3 §4.3 悬案 **本轮静态确认，结案** ✅

## 4 密钥扩展与计数器（✅ 本轮复核 `sub_CB4580` / `sub_CB4970`）

### 4.1 ctx 布局（`sub_CB4580(bits, key16, ctx)`）

```
if (bits == 128):
    sub_CB43E0(&v47, key16)      // 载入 16B 主密钥 KL
    ctx[0..3] = v47..v50         // ★ ctx[0..3] = KL（= 前 4 字节密钥）
    ctx[4..7] = v55..v58         // 128 位档下 v3/v4 = 0 ⇒ 全 0
    // 随后生成 44 个 dword 子密钥写入 ctx[8..51] ⇒ 共 52 dword
    return 88
```
⇒ ★ **`ctx[0]` 被覆盖为 `KL[0]`**（若 ctx 是全新分配则本来就是 KL[0]；关键是**加/解密前的第 1 个白化子密钥就是 `ctx[0]`**）。

### 4.2 加解密块（`sub_CB4970` / `sub_CB4AD0`）

```
sub_CB4970(bits, in, ctx, out):     // 加密
    sub_CB43E0(out, in)             // 载入 16B 明文
    out[0] ^= ctx[0]; out[1] ^= ctx[1]; out[2] ^= ctx[2]; out[3] ^= ctx[3];   // ★ 白化 = ctx[0..3]
    ...18 轮 F 函数（sub_CB4450）...
    末白化 ^= ctx[最后 4 dword]（含半字交换）
```
调用侧（`sub_C882F0` / `sub_C88510`）**每块后 `++ctx[0]`**：
- 出站：`sub_CB4970(128, in, this+164, out); ++this[164];` ⇒ `++ (+0x290)[0]`
- 入站：`sub_CB4AD0(128, in, this+232, out); ++this[232];` ⇒ `++ (+0x3A0)[0]`
⇒ 语义 = **`KL[0] + 该方向累计块数 (mod 2^32)`**，跨帧跨连接持续累加、**代码内无任何复位点** ✅
⇒ 与 `server/camellia128.py`（`w[0] += counter`）完全一致。

### 4.3 算法身份

`sub_CB4580` 的 128 位分支 + `sub_CB4970/sub_CB4AD0/sub_CB4450` + 官方向量通过 ⇒ **标准 Camellia-128**；
唯一非标准 = 计数器加到第 1 个白化 dword（`ctx[0]`）⇒ 服务端必须同步。
