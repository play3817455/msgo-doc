## 0. 一句话结论

登录入口**不产生任何报文**：`sub_A88920`（登录 FSM）把用户输入的账号/密码以 `std::wstring` 收进 `FSM+20/+48`，
在 state15 由 `sub_43E3F0` 转成 **UTF-8 明文**（`sub_BC3FB0`，CP=0xFDE9）拷进 `app+28`(账号) / `app+541`(密码)，
并把账号/密码塞进步骤对象 `CGameStateStepUpdateLoginAuth`（vftable `0xD68014`）的 **`+20`(账号)/`+533`(密码)**；
**全程无 MD5、无哈希、无加密**（本轮再次确认为负证据）。凭据文件 `account.ini` 是一个
**`键,值` 的 map 快照**（**按 key 升序输出、CRLF、UTF-8 无 BOM、无 section 头**），只有三个键：
`AUTH`(记忆账号索引) / `ID`(账号) / `ID/PW_SAVE`(0|1)，**密码从不落盘**。

## 3. 文件与格式

### 3.1 `account.ini`（★本轮新增磁盘字节级证据）

**位置**：客户端工作目录（实测两处内容一致：`GundamOnline\account.ini` 与 `GundamOnline\data\account.ini`）

**原始 32 字节**：

```
41 55 54 48 2C 31 0D 0A | 49 44 2C 61 64 6D 69 6E 0D 0A | 49 44 2F 50 57 5F 53 41 56 45 2C 31 0D 0A
A  U  T  H  ,  1  \r\n | I  D  ,  a  d  m  i  n  \r\n | I  D  /  P  W  _  S  A  V  E  ,  1  \r\n
```

⇒ 文本 = `AUTH,1\r\nID,admin\r\nID/PW_SAVE,1\r\n`

| 属性 | 值 | 证据 |
|---|---|---|
| 编码 | **UTF-8，无 BOM** | 首字节即 `A`（`0x41`），无 `EF BB BF` |
| 行尾 | **CRLF**（`0D 0A`） | 逐字节 |
| 结构 | **无 `[section]` 头**；每行 `键,值` | 逐字节（`nodes/01 §5.5` 的疑问 ⇒ **答：无 section**） |
| 输出顺序 | **按 key 升序**（`AUTH` < `ID` < `ID/PW_SAVE`，且 `ID` 是 `ID/PW_SAVE` 的前缀） | 文件顺序 ≠ 代码写入顺序 ⇒ 底层是 `std::map` 语义 |
| 键数 | **恒 3 个**（缺项不影响读取，读到的值走默认） | `sub_433E60`/`sub_434140` |
| 密码 | **从不写入** | 代码里只写 3 个键 |

**读**（`sub_433E60`，本轮反编译，顺序 = 代码顺序）：

```
sub_46F2F0(reader)                    // 构造
sub_402AD0(&path, "account.ini", 11)  // 路径（11 字符）
sub_46F080(reader, path, 1, 1)        // 打开（不存在则空 reader）
app+114204 = 0                        // 默认 PW_SAVE = 关
读 "ID/PW_SAVE"(len10) → 命中 ⇒ app+114204 = (atoi(v) != 0)     // sub_CC6876
if (app+114204) 读 "ID"(len2) → 命中 ⇒ wide→UTF-8 → sub_CC65C6(app+28, 513, s, 512)
读 "AUTH"(len4) → 命中 ⇒ app+1056 = atoi(v)

```

★ 要点：**`ID` 只在 `ID/PW_SAVE` 非 0 时才读**（未勾"记住密码"⇒ 一律不预填账号）。

**写**（`sub_434140`，本轮反编译，顺序 = 代码顺序）：

```

写 "ID/PW_SAVE" ← (app+114204 ? L"1" : L"0")      // 字面量实测：0xD681D4=L"1"，0xD681D0=L"0"
写 "ID"        ← sub_BC4110(app+28)               // UTF-8 → wide
```

## 6. 对服务端落地的影响

- **认证链的凭据是「UTF-8 明文 + 无哈希」**：服务端实现登录校验时必须按此假设（`nodes/01 §5.1` 的三选一
  仍留待 W02 判定：是否需要 MD5 属 `:1633` 平台链 / `LoginAuth` 步骤内部）。
- **`account.ini` 只影响客户端预填**，服务端无需关心；但**联调时清/改它可控制"自动填的账号"**，
  是自动化复现的一个可用旋钮（例：把 `ID,admin` 改成别的账号即可换登录账号，**无需改客户端配置**）。
- **`ID/PW_SAVE=0` ⇒ 客户端不预填账号**（但仍会读 `AUTH`）——做"全自动跑链"时应保持 `1`。
