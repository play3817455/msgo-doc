## 0. 一句话结论

**匹配/进房成功后，`btlroom_enter_r`(0x5383) 把 `battlesv_host/battlesv_port/otp_battle` 写给客户端 → `sub_442970` 建 `CGameStateStepUpdateLoginBattle`（vtable `0xD68474`）→ 其 tick `sub_440080` 用 `sub_AF7400`→`sub_AF7130`（**与 auth/lounge 完全相同的连接 helper**）对战斗服 host:port 主动发起 **第 3 条 TCP 连接**（复用 N3 access 握手 + Camellia 帧层 + LZP）→ 就绪后发首包 **`0xF24B`（battle 变体 authenticate）** → 应答 **`0xA5DA`（authenticate_r，20 字段）**。**

★战斗服 = 启动时就存在的**第 3 个 VCE 协议对象 `CGVOProtoBattle`**（全局 `dword_1201A64`），**不是** lounge 的复用；其收包分发器 `sub_B0CC20`、帧类型解析器 `sub_C84B60`（=N3 帧层）、发送 `sub_C85050` 与 auth/lounge 同槽位布局。

## 2. 状态机（`sub_440080`，LoginBattle.tick）

```
switch (this+4) {
  case 0:  sub_AF7400(host, port) 成功 → state=1；失败 → state=10
  case 1:  sub_AF7070() 未就绪 → return 0（等下一帧）；就绪 → state++（fallthrough 到 case2）
  case 2:  组首包参数 → sub_BAADC0(...) 成功 → state=3；失败 → state=10
  case 3:  return 0（完成）
  default: return 1
}
```

- 首包参数来源（case2）：`userid=dword_11FFB44`、`world_id=app+0x46C(1132)`、`pilot_id=this+196`、`room_id=this+200`、`otp=this+149`、`is_comeback=(app+0x1BDAC != 0)`。

## 6. 对服务端落地的影响

1. **战服 = 第 3 条 VCE 会话**：服务端为每个客户端提供 1 条战斗连接即可（星型，非 P2P），可直接复用 auth/lounge 的 iVCE 帧层 + Camellia 握手代码。
2. **首包解析**：battle `0xF24B` 体 = `userid/world_id/pilot_id/room_id/otp_battle(NUL)/is_comeback`（7 字段，非 lounge 的 2 字段）；服务端必须按此变体解析。
3. **必须回对 `0xA5DA`**（20 字段，体长 630+len(room_name)）——这是"战场会话初始化"入口，`room_id/mission_id/map_id/team` 等必须合理值，否则 `sub_448FE0` 之后战场状态机不成立。
4. **`0x5383` 必回真实 battlesv_host/battlesv_port/otp_battle**（W17 已定）：回对后客户端才建 LoginBattle 连战斗服；这是"能出击"的最后一跳。
5. 首屏后是 `0x1365 game_begin`（战场全局参数，23 字段，B03/B04）→ `msma_spawn_*` 出击族 → 实体快照/伤害循环（B05/B06），逐字段是后续 battle 工作项。
