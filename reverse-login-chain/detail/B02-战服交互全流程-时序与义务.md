## 0. 一句话模型

**客户端**：本地模拟自己的移动 + 本地弹道/命中判定 + 托管部分 NPC AI；
**服务端（战斗服）**：接收各客户端上报 → 算伤害/HP → 聚合广播世界快照 → 记分/胜负 → 全程仲裁（hack_check、pos_warp_force）。
**拓扑**：星型（客户端 ↔ 战斗服，单连接）；**协议规模**：S→C 205 条、C→S 92 条；**体长**：143/205 已定。

## 2. 进战场（S1）时序

```
[lounge 30001]
  S: 0x5383 recv_btlroom_enter_r  { battlesv_host, battlesv_port, room_id, otp }   ← 服务端给出的战场地址
  C: 结束 lobby 会话并 mode=2（本机实测 app+0x1BDAC=2、FSM=21）

[battle: 客户端主动 connect(host,port)  —— 与 auth/lounge 同一 helper sub_AF7130（TCP）]
  C: 0x34A9 proto_version_check { version, crc, gentime }        (3 参)
  S: 0xDE24 proto_version_check_r { version, crc, gentime }      (12B ★定长)
  C: 0xF24B authenticate { userid, world_id, pilot_id, room_id, is_comeback }   (5 参；battle 变体)
  S: 0xA5DA authenticate_r  (20 参，alloc 0x2DE)  → 客户端 handler sub_BA8C20 → sub_AFAB40 → sub_448FE0(app, 21 参)
       字段序：result, room_id, mission_id, extrule_id, dc_node_id, is_rankerbattle, map_id, is_vsclan,
               comeback_stat, is_playing, is_netcafe, team, is_practice, config, progress,
               expup_fgauge, is_ev_caravan, flag_wideuse, extrarule_xwar_info   ★=进场参数总入口
  S: 0xBA73 cpf_authenticate { data[] }        → C: cpf_authenticate_r { data[] }   （反外挂握手）
  S: 0x2C60 cpf_authenticate_error { result }  （失败分支）
```
★**服务端要点**：`authenticate_r` 是"战场会话初始化"，19~20 个值直接喂 `sub_448FE0`（与登录期那个"初始化 21 参数"是同一函数，见 §6 更正）；`room_id/mission_id/map_id/extrule_id/team/config/progress` 必须给合理值，否则战场状态机不成立。

## 6. ⚠️ 顺带更正登录链的一处归属
登录链文档把 `[obj+0x108]` 的槽地址算成 `0xEED81C`（用了 auth 表基址 0xEED714），并据此把 `sub_BA8C20`（→`sub_AFAB40`→`sub_448FE0`）归给"lounge/auth 的某条报文"。
实测：**`0xEED81C` 属于 `CGVOProtoBattle` 表**（基址 `0xEED7AC`，`+0x70`），即 **`recv_authenticate_r`(0xA5DA) 的 handler**。
⇒ `sub_448FE0(app, 21 参)` 应理解为**"服务器会话初始化（21 参）"**，登录期（auth/lounge）与战场（battle authenticate_r）**共用**；"它置 `app+416220=1`" 这条实证不变（FSM 门），但"它只挂 auth 表 +0x108"的归属需要改。
（三表基址：auth `0xEED714`（很短，≲38 槽）、**battle `0xEED7AC`（237 槽）**、lounge `0xEEDB6C`；各自的收包分发器都在 **+0x54**。）
