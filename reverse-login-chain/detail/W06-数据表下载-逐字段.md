## 0. 一句话结论

大厅（30001）认证成功（`0xF24B→0xA5DA` 8B）后，客户端进入**数据表串行下载泵**：读本地 `settings/download_list.csv`（76 行）→ 每行 `KEY` 经键表 `0xD783E0` 翻译成**处理器 ID（0..79 缺 78）**→ 插入 `std::map<处理器ID, 文件名>` → 每帧取 **ID 最小**节点发 `0xF86A` → 服务器回 `0x5290`（7 字段）→ 按 `filepath` 反查节点拿 ID 走 80 路 switch 装载 → 删节点 + 置位 → 下一帧发下一个。**请求顺序 = 处理器 ID 升序，不等于 `download_list.csv` 行序**。泵**只认成功**推进：`result<0` / `compress∉{0,1}` / 脚本解析失败 / `filepath` 反查失败，四种情况**都不删节点、不置位、无重试无超时 ⇒ 永久死锁**。服务端必须按 ID 升序逐张应答非空合法 UTF-8 内容，`filepath` 逐字节回显。

## 2. 状态机

### 2.1 下载泵状态机（`CDataTableDownload`）

> 状态字段：`(泵+0x10) bit0` = CAN_SEND；`map._Mysize` = 剩余表数。本轮逐函数坐实：

```
        IDLE（bit0=0）：每帧 sub_576140 直接返回（不做事）
             ▲
             │ 初始化 / 上一张成功（sub_576160 末尾 *(泵+16)|=1）
             ▼
        SEND（bit0 被清）：sub_5760B0
             ├ map._Mysize==0 ⇒ return 0（链路结束，永不再起）
             └ 否则取最左节点（ID 最小）→ 文件名 → ANSI → 0xF86A
             ▼ 服务器回 0x5290
        PARSE（sub_576160）
             ├ filepath 反查 map 失败 ⇒ 静默 return  ┐
             ├ sub_BBBD70 / sub_AEDCF0 失败          ├ ★不删节点、不置位 ⇒ 永久死锁
             ├ result<0 / compress∉{0,1}（sub_BAAFF0）┘   （无重试、无超时）
             └ 成功 ⇒ switch(ID) 装载 → sub_A4A020 删节点 → bit0|=1 ─→ SEND
```

| 状态/条件 | 位置 | 取值 | 含义 | 进入/退出条件（本轮证据） |
|---|---|---|---|---|
| `CAN_SEND` | 泵 `+0x10` bit0 | `0/1` | 是否允许发下一个 | 进入：`sub_576160` 成功后 `|=1`；退出：`sub_576140` 先 `&=0xFE` 再 `sub_5760B0` |
| 剩余表数 | map._Mysize（`+0xC`） | `0..76` | 未完成表数 | 填满于 `sub_576CC0`；每成功 `sub_A4A020` 递减（`this[2]--`）；=0 ⇒ 静默停机 |
| 初始发送 | `sub_576CC0` 末尾 | — | **不经 bit0** 直接 `sub_5760B0` 发第 1 个 | 读 CSV 成功 / 兜底插入后各调一次 |
| 兜底 | `sub_576CC0` | `{78, "msma/msma_overwrite_params.csv"}` | CSV 读失败时唯一一张表 | `sub_AEFD80` 返回 0 |

**推进条件（回答"何时请求下一个 / 完成标志 / 失败是否重试"）**：
- **请求下一个**：每帧最多一个，条件是「上一张解析成功置了 bit0」且 map 非空（`sub_576140` → `sub_5760B0`）。
- **完成标志**：**无持久标志**；`map._Mysize==0 ⇒ sub_5760B0 return 0`。泵对象每次进大厅由 `sub_42E9B0` **重建** ⇒ 每次登录重下全部 76 张。
- **重试**：**不存在**。四种失败（`result<0` / `compress∉{0,1}` / 解析失败 / filepath 不匹配）都保持 bit0=0 且不删节点 ⇒ 永久死锁。

### 2.2 "空内容必卡"双锁定案（本轮坐实）

1. `sub_BBBCD0(size=0)`：`sub_BDC240(0,…)` 分配失败（或返回非法的 0 大小缓冲）→ `this[1]=0` → 返回 `-2146435072`。
2. `sub_AEDC30`：`MultiByteToWideChar(0xFDE9=CP_UTF8, 0, str, cbMultiByte=0, 0, 0)` 返回 0 ⇒ 走 `else` 返回 `-2146435072`（**即使第 1 道锁放行，转码长度 0 也判错**）。
**任一道都够让 `sub_AEDCF0` 返回非 0 ⇒ `sub_576160` 不删节点不置位 ⇒ 泵死锁。**

## 3. 报文/文件逐字段表（★核心交付）

> 通道 = `:30001`（lounge）。NUL 变长串 = `sub_B02B40`(写)/`sub_B02BA0`(读)；u32 = `sub_B02DD0`；u16 = `sub_B02DF0`；u8 = `sub_B06230`。每 case 末尾 `游标 == 报文尾`，否则整包丢弃。

### 3.1 `0xF86A` datafile_download（C→S，请求）

| 线上偏移 | 类型 | 长度 | 含义 | 取值域/必须非零 | 证据（本轮反汇编） |
|---|---|---|---|---|---|
| +0 | u16 | 2 | **报文 ID = 0xF86A** | 恒 `0xF86A` | `0xB89C69: mov word ptr [ebp+0], 0F86Ah` |
| +2 | str(NUL) | 变长 ≤256 | **filepath**（服务器文件名，如 `msma/msma_weapon_set.csv`） | 与 `download_list.csv` 第 1 列一致；必须 NUL 结尾 | `0xB89C73: call sub_B02B40(a2,&cur,256)`（`push 100h`） |

- **日志串**：`")<-_proto_lounge_client::send_datafile_download( "` + `filepath="…"` + `hashval=…` + `)[N]byte`。

| 字段 | 值 | 依据 |

## 6. 对服务端落地的影响

- ★ **0x5290 应答顺序**：服务端必须维护"请求序列"并按 ID 升序应答；`server\datafiles\`（75 CSV 种子 + autoexec_sv.cfg 真实内容）已覆盖，`access_sticky.py`/Go 的 `0xF86A` 分支已按 filepath 分发（继承 topics/13 §十一）。
- ★ **filepath 回显铁律**：应答的 `filepath` 必须与请求**逐字节相同**（`sub_576160` 按 wstring 全等反查 map），否则静默丢弃 ⇒ 卡死。
- ★ **content 最低要求**：非空 + 合法 UTF-8（两道锁）；真实列定义可后补（越界列=0，`JAPAN` 行丢弃，枚举写名称）。
- ★ **无重试**：任何一张 `result<0`/`compress∉{0,1}`/解析失败/filepath 不匹配，客户端永久停在该 filepath ⇒ 排障先看 `server\logs\datatable.log` 最后一条。
- ★ **每次登录全量重下 76 张**（`sub_42E9B0` 重建泵、无持久标志）⇒ "按 filepath 分发"是刚性需求，改 `server\datafiles\` 下次登录立即生效。
