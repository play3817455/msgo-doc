# B05 · 出击流程（msma_spawn_*）取证 —— 让"机体出现"

> 2026-09-15 IDA 实测（`unpacked\GundamOnline_CHINA_v15.exe.i64`）。配套：`formats\battle-交互总表.md`（行号可查）。
> 目标：服务端要能完成 **"开局 → 候选机体列表 → 玩家选机/选点 → 倒计时 → 机体出现"** 这条链。

## 1. ★核心结构定案（三个子结构 = 同一套"**预留槽位 + 紧包线序**"机制）

客户端对复合字段的读法（`entity_msma_appear` 0x717D 的 case 实测）：
```
sub_B05FF0(&ms_ptr,        &cursor)   → 预留 ms      槽：*a2 += 264
sub_B06D80(&ms_struct,     cursor)    → 从包读 ~244B 填 264B 槽
sub_B06010(&snapshot_ptr,  &cursor)   → 预留 snapshot 槽：*a2 += 44
sub_B075A0(&snapshot_slot, cursor)    → 从包读 39B 填 44B 槽（= B06 那条 44B 实体条目）
sub_B41460 + sub_B081C0               → funnelss：u32 + u8 + u8×5 = 10B
```
**规律**：`sub_XXXXXXXX(&slot, &cursor)` 只做"**记起点 + 跳过 N 字节**"（懒解析），随后专门的解析器把**紧凑线序**读进**带对齐空洞的内存槽**。
⇒ 服务端只需按**紧凑线序**拼字节，不必管空洞。

| 子结构 | 内存槽 | 线序字节 | 解析器 |
|---|---|---|---|
| `ms`（出击机体 264B） | **264** | **244**（20B 空洞） | `sub_B06D80` |
| `snapshot`（外观/状态快照） | **44** | **39**（5B 空洞） | `sub_B075A0`（同 `entity_snapshot`） |
| `funnelss`（浮游炮组） | 10 | 10 | `sub_B081C0` |

交叉验证：`msma_spawn_list_get_r_one`(0x1E2F) `alloc=0x10C=268=4(index)+264(ms)` ✓；
`entity_msma_appear`(0x717D) `alloc=0x156=342 ≥ 1+1+4+4+264+44+10+2+2+5=337` ✓；
`entity_msma_appear_self`(0x7621) `alloc=0x154=340 ≥ 1+1+264+44+10+16+2=338` ✓。

## 5. ★服务端要实现的最小"出击"状态机（建议）
```
[房间就绪] S→C roomlobby_game_start_r(0x7206) / S→C game_begin(0x1365)   ← 地图/任务/快照节拍/重生点/胜负目标
      ↓
C→S msma_spawn_list_get(0xE041)
S→C msma_spawn_list_get_r_begin(0x9951) → _r_one(0x1E2F)×N（每个候选机体一条 264B ms）→ _r_end(0xAB6F)
      ↓
C→S msma_spawn_select(0xE650)   （ms_index / post_index / spt_spot_index / 是否乘战舰/机体 / respawn_ent_id）
S→C msma_spawn_select_r(0x86B2) （result + 复述选择 + respawn_ent_id + script_ini）
      ↓（可选）S→C msma_spawn_info_prestart(0x640D) 倒计时预告
C→S msma_spawn_warp_select(0x800A) → msma_spawn_warp_start(0x7B52)
S→C msma_spawn_warp_start_r(0xFEBB)（result/is_cancel/ent_id/countdown_msec）
S→C msma_spawn_warp_countdown_finish(0xE5FC)（ent_id）
      ↓
S→C entity_msma_appear(0x717D)   ← ★其余人看到"这台机体出现了"（含 ms/snapshot/funnelss）
S→C entity_msma_appear_self(0x7621) ← 自己（多 hp_now/max/shield）
S→C entity_msma_show_hp(0xE4DB) / entity_snapshot(0x568A) 起，进入移动同步（见 B06）
      ↓
死亡循环：entity_msma_dead(0x9105) → msma_spawn_wait_update(0x8DE4)/game_respawn_post_update(0xD1B3)
          → 重新 msma_spawn_warp_select/warp_start → entity_msma_reborn(0x1EA5)
```
配套（装备/换武器）：C→S `eqparts_ready_start/cancel`、`active_weapon_change/mode_change`、`funnel_snapshot_self`；S→C 对应 `_r/_notice/_toggle`。

## 6. `entity_msma_appear` 的业务链（已跟到"惰性消费"）

```
case 0x717D（14 参，顺序 == dump 字段顺序 1:1）
  push 54h; call sub_B05D90                       // vt 分派
   → handler sub_BA94F0(a1..a14)
        if (a12 /*is_using_ss*/) sub_AA2EF0(a6 /*snapshot*/);
        → sub_AFD970(team, troops, world_id, pilot_id, ms, snapshot, funnelss,
                     unattended_state_bit, weapon_state_bits, target_icon, is_respawn,
                     stghold_number, xweapon_fired)
           ├─ v14 = ((int*)ms)[2]; sub_581200(&out, &v14)   // 用 ms+8 的 u32 查实体/类型
           ├─ 若 type==9: sub_4C0F80(&out, ent_id, list, pos_x, pos_y, pos_z, dir, …)
           └─ 否则: v17 = sub_44FC00(pilot_id, world_id);
                    sub_4C2D20(&out, 2, v17, team, troops, ms, snapshot, funnelss,
                               100, 100, 0, 0, unattended_state_bit, stghold_number,
                               is_respawn, weapon_state_bits, target_icon, xweapon_fired, 0)
```
`sub_4C2D20` 内（实测）：
- `*a8`(= snapshot 的 word0) 作 **ent_id**；`v22 = a7[2]`；`sub_62E3D0(…, *a8, …)`
- `sub_478EE0(x, ms_ptr, 0)` → `this[64] = x; this[65] = ms_ptr;` ⇒ **ms 指针被实体"暂存"**，机体模型的真正构建在其后（惰性）。
⇒ 想给 264B 定名，要沿着"实体构建/模型加载"那条链走（`sub_478EE0` 的 `this[65]` 消费点）。
