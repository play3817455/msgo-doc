## 0. 一句话结论

认证连接（30000）上是一个**收发对称的门控式协议对象**：类的 vtable 第 21 项 `sub_B03D30` 是收包分发器，
按帧首 `u16 ID` 做二叉搜索，只认 **8 个 ID**（`0x1146/0x298E/0x4F3F/0x60E0/0x8F36/0xA103/0xA5DA/0xDE24`），
每个 case 校验完字段后调 vtable 第 26~33 项的业务回调（`sub_BA8B60`…`sub_BA8A70`）；
发送侧由 5 个函数构造，报文体一律是 `u16 ID + 字段`，**所有变长字段都是 NUL 结尾的变长串**（读取器 `sub_B02BA0`），
且每个 case 都要求"**游标恰等于报文尾**"；世界条目线上 **309B/条、count ≤ 32**。
★ 三条对旧表的重要修正：① `0x8288` 的 send **体为空（仅 2B ID）**，`last_world` 是服务端**下发**的；
② `0xA380` 的 send 体 = `u32 world_id + u32 channeling_type`（10B），旧表把 `0x1146` 的**应答**字段写成了它的发送体；
③ `0x3B8F` send 仅 2B。
★ 最要命的机制：该类的"协议错误回调"vt[25] = **`nullsub_35`（空函数）** ⇒ 任何字段/长度不合法都**静默丢弃**，
不断开、不重试、不提示——这就是"定长填充字符串会被丢弃"的根因（详见 §3.3）。

## 2. 状态机

### 2.1 协议门控（`sub_B02C90`，每个收包必经）

```
sub_B02C90(this, n):                                   // n = 报文序号(见下表)
  if (this[n+108] == 0)      → cb(this, n, 2); return 0   // 该报文当前"不允许接收"
  rec = &this[48*n+128]
  if (qword@rec+16 != 0) {                               // 仅当装了"时间预算"才校验
      sub_B02C00(rec);
      if (rec[0] > rec[1])   → cb(this, n, 3); return 0   // 超出预算
      ++rec[0];
  }
  return 1
```

* `cb` = **vt[25] = `nullsub_35`（空实现）** ⇒ 三种失败码（0=未知ID / 1=体长不符 / 2=门控关闭 / 3=超预算）**都只被静默吞掉**。
* 两组许可位由基类初始化 `sub_B02F10` **一次性全置 1**（`0xB02FD0` 写 `this[108+i]`、`0xB02FD4` 写 `this[92+i]`，循环 16 次）：
  即"默认全开"，报文序号空间是**统一的 16 槽**。
* 已出现的槽位：**send** = 0(`0x34A9`) / 2(`0x2C1A`) / 10(`0x8288`) / 12(`0xA380`) / 14(`0x3B8F`)；
  **recv** = 1(`0xDE24`) / 3(`0xA5DA`) / 4(`0xA103`) / 6(`0x60E0`) / 9(`0x8F36`) / 11(`0x298E`) / 13(`0x1146`) / 15(`0x4F3F`)。

### 3.3 ★ 字符串与游标规则（"定长填充会被静默丢弃"的根因）

```
sub_B02BA0(dst, cursor, limit):            // 读一个 NUL 变长串
  n = min(limit, end - *cursor)
  if (n < 0) return 0
  p = memchr(*cursor, 0, n)                // sub_CC8400
  if (!p) return 0                         // ★限制内找不到 NUL ⇒ 失败
  memcpy(dst, *cursor, p + 1 - *cursor)    // 拷贝"含 NUL"
  *cursor = p + 1                          // ★游标停在 NUL 之后，不是"字段末尾"
  return 1
```

* 发送侧对称：`sub_B02B40(src, cursor, limit)` 写"串 + NUL"。
* 每个 case 结束都做 `if (p != end)` 判定；不等即报错。
* 报错回调 `vt[25]` = `nullsub_35`（`0x691680`，**空函数**）。

**⇒ 两种"定长填充"都会整包被静默丢弃：**

1. **填入的字段内没有 NUL**（例如 49B 全填非零/空格）：`memchr` 在 limit 内失败 ⇒ `sub_B02BA0` 返回 0 ⇒ 落错误分支。
2. **字段含 NUL，但 NUL 之后还有填充字节**：游标停在第一个 NUL 之后，后续字段整体前移 ⇒ 最后 `p != end`（或字段错位读出垃圾导致解析失败）⇒ 落错误分支。

**正确做法（服务端造包铁律）**：变长字段一律 **NUL 结尾、各字段首尾紧贴、报文尾不得有任何填充/对齐字节**，
长度上限只是"读取上限"而非"字段宽度"。
