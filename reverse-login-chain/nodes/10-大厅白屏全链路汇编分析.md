## 一、收包管线（30002 频道服）

```
socket 收包 → 拆帧 → 报文分发器 sub_B51930（0xB51930..0xB89116，约 226KB）
                         │
                         ├─ 每个 case：push <序号>; call sub_B41120        ← 准入闸门
                         ├─ 逐字段解析（游标 + 末尾 cmp cursor,end 严格相等）
                         ├─ 自动生成的"报文 dump"（拼 src="…" val1=… val2=… 调试串）
                         └─ 业务调用（vt[0x14C] / vt[…]，各报文不同）
```

### 1.1 准入闸门 `sub_B41120(this, idx)`（0xB41120）

```c
if (!this[idx + 713]) { this->vt[100](this, idx, 2); return 0; }   // 未使能 ⇒ 静默拒收
if (*(QWORD*)&this[48*idx + 1352]) { … 计数/时间窗超限 ⇒ vt[100](idx, 3); return 0; }
return 1;
```

* 使能位是**逐索引 1 字节**的数组：`app + 0x2C9 + idx`（`713 = 0x2C9` ✓）。
* **数组真实范围 = `app+0x5C .. app+0x2C9`（0x26D = 621 个条目）**，
  由初始化函数 **`sub_B47420`（0xB47420）** 一次性**全部置 1**：

  ```asm
  0xb47484: lea eax, [esi+2C9h]        ; esi = app
  0xb4748a: mov ecx, 26Dh              ; 621
  0xb47490: mov byte ptr [eax-26Dh], 1 ; 起点 = app+0x5C
  0xb47497: mov byte ptr [eax], 1
  0xb474a0: jnz short loc_B47490
  ```

* ⇒ **默认全开** ✓（所以"客户端把我们的包静默丢掉"**不是**闸门造成的 ✗，
  这条曾在 2026-09-15 被误判为白屏主因，此处明确排除 ✓）。

### 1.2 `0xA64A channellobby_script_play`（服务端→客户端）

* case 入口 **`0xB7061C`**（`push 63h; call sub_B41120` ⇒ 索引 `0x63`）；
  接收日志串 `recv_channellobby_script_play` @ `0xee7574`，xref = **`0xB7071F`**（在本 case 内 ✓）⇒ 归属确认 ✓。
* **读体**（`0xB7062D..0xB706E0`）：

  | 字段 | 读取器 | 宽度 |
  |---|---|---|
  | 脚本名 | `sub_B02BA0(dest,&cur,0x41)` | **NUL 结尾串，cap 65B** ✓（⚠️不是定长 ✗） |
  | val1 | `sub_B02DD0` | u32 |
  | val2 | `sub_B02DD0` | u32 |

  ⇒ **体 = `name | 00 | u32 | u32`，长度 = len(name)+9（可变）** ✓；
  末尾 `cmp cursor,end; jz OK` ⇒ 游标必须**恰好到底** ✓。
  ⚠️ 踩坑：曾按"定长 65B + 8 = 73B"发 ✗ —— `vt[0x78](0x49=0x49)` 那个 **73 是客户端结果结构体**大小
  （65B 名字缓冲 + 2×u32），**不是体长** ✗；73B ⇒ 游标 30≠73 ⇒ 走失败分支 ⇒ 整包丢弃 ✗。

* **业务段（关键）**：

  ```asm
  0xb70824: mov edx, [esi]        ; esi = client
  0xb70826: mov edx, [edx+14Ch]   ; ★vt[0x14C]
  0xb7082f: mov eax, [esp+var_2C20]; 解析出的名字（65B 缓冲）
  0xb70833: push ecx(val1) / push eax(name) / push val2
  0xb70837: call edx              ; ★client->vt[0x14C](name, val1, val2)
  0xb70839: add dword ptr [esi+17E8h],1   ; 成功计数 +1（可用于验证"包被吃掉了"）
  ```
  ⇒ **这条报文唯一的作用就是 `vt[0x14C](name,val1,val2)`** ✓；其余全是自动生成的 dump 代码 ✓。

* 语义证据：`script/UI/Lobby_Official.nut` 头注释 =「大規模戦選択後（オペレーター表示）」；
  客户端有 `/lobbyscript <名字.nut>` 机制，名字**不带 `script/` 前缀** ✓。

## 二、场景系统（白屏的"物理机制"）

| 字段 | 偏移 | 说明 |
|---|---|---|
| 场景管理器指针 | `app + 0x1BE24`（`this[28553]`） | 非空 ✓ |
| 场景栈 vector | begin `app+0x1BE2C` / end `app+0x1BE30` / cap `app+0x1BE34` | 真机读数 **begin == end** ⇒ **栈空** ✗ |

* **`sub_43A350(app, sceneID, fade)`（0x43A350）= 切场景（并压栈）**：

  ```c
  manager->vt[844](fade);           // 转场
  manager->vt[848](激活对象);        // ★显示该场景
  stack.push_back(sceneID);         // ★压栈
  ```

* **`sub_438D10(app, sceneID)`（0x438D10）= 弹场景**：

  ```c
  从栈里删掉 sceneID → 若栈非空：取新栈顶 → manager->vt[848](obj) ⇒ 显示
                      → 若栈空：  manager->vt[656]()           ⇒ ★什么都不显示 = 白屏 ✓
  ```

* **`sub_43ADD0`（0x43ADD0）= 登录/首屏状态机**（`this+1396` = 状态，`this+1400` = 门位位图）：

  | 状态 | 行为 |
  |---|---|
  | 6 | `sub_43A350(13, 0.0)` ⇒ **切到场景 13**（「正在変更頻道」转场画面） |
  | 0x10 | 门 `& 0x400` ⇒ 17 |
  | 0x14 | `v6 = *(DWORD*)(this+114092)`（`app+0x1BDAC`）；`v6==2` ⇒ `sub_442970()`；否则直接 21 |
  | **0x15** | `sub_438D10(this, 13)` ⇒ **把场景 13 弹掉** ⇒ 露出下面那个场景；**栈空 ⇒ 白屏** ✓ |

  ⇒ **设计意图：13 是临时转场场景，弹掉后应露出"大厅场景"** ✓ ⇒
  **只要有人先把大厅场景压进栈，白屏就会自动消失** ✓✓。

## 六、可直接复用的方法（本轮沉淀）

1. **定位字段读写**：把字段字节编码成 disp32 后 `find_bytes`（例：`app+0x1BDAC` → `AC BD 01 00`；
   `app+0x2C9` → `C9 02 00 00`）⇒ 一次列全读写点 ✓，比逐函数翻快一个数量级 ✓。
2. **报文归属唯一权威 = `recv_*` 日志串的 xref** ✓；`cmp eax,ID → jz` 只说明"该 ID 去哪个 case" ✓，
   两者不一致 ⇒ 那是**另一条报文**的 case ✗（`0xCCDF` vs `0xCE1A` 的教训 ✓）。
3. **体长求法**：逐条数"线读" → 未知读取器**先反编译看它吃多少**（NUL 串=变长 / `for i<N` 逐字节=定长）→
   用 `vt[0x78](N)`、末位 `cmp cursor,end` 交叉验证 ✓。
4. **内存取证**：`debug_init` 自己拉起才能读内存 ✓；attach 模式下读不可用 ✗。
